# 评测系统：当前可以诚实展示什么

目前工程和真实验证已形成一个小规模闭环，但还不能写成“大规模成熟评测已完成”。真实实验详情见 [首轮校准报告](../evaluation/real-pilot-20261002.md)。

## 可使用的简历描述

为研究型 Agent 搭建本地可复现评测工作流，隔离运行原生 Ragas 质量指标，记录完整答案、证据、轨迹和 Token；实现运行/批次请求限额、实验身份校验、逐运行落盘与断点复用。完成 1 道真实官方资料题的 Baseline / Harness 对照及 16 次真实评分调用，保留失败样本，定位回答截断与证据支持不足问题。

续建后可加一句：实现题内重复聚合、题级配对 bootstrap 与覆盖率统计；通过正常应用与隔离 SQLite 完成 6 类、12 个记忆生命周期场景 × on/off 共 24 个受控变体，验证跨会话召回、TTL、更新/删除和 namespace 隔离。受控变体不能称为真实模型质量评测。

数字较少时可以省略题数，但不能替换成尚未实测的 30 题、178 次运行或提升百分比。工程回归测试数不是质量评测样本数，最新验证见各轮报告。

## 面试官问：与你调用一个成熟 DeepResearch 有什么区别？

我的重点不是宣称模型或研究效果超过商业产品，而是把研究 Agent 做成可以诊断、对照和改进的工程系统。相同题目、模型、资料与上限下，把固定检索回答和 Harness 拆开比较，保留完整输入输出、原始证据、工具执行和资源消耗；质量评分与生产运行解耦，评分失败不需要重新调用 Agent。

这让我能回答“为什么失败、到底哪层在起作用”。例如首轮 Harness 虽然 completed，目标指标也为 1，但证据忠实度只有 0.48；它引用了一个没有包含 Store 说明的来源来说明跨线程记忆。Baseline 则资料覆盖更完整，但输出两次被截断，最终是 partial。只看成功状态或引用格式，这两个问题都容易被掩盖。

我不会把自己的 Baseline 说成商业 DeepResearch：这次工具是冻结真实资料，不是实时全网搜索；裁判与 Agent 同模型，只有一个开发校准题，尚未完成人工复核。要证明稳定收益，还需要更多冻结测试题、题内重复聚合、配对统计及人工盲评。

## 应当能讲清楚的细节

- 一次 Ragas 指标不等于一次 API 调用：faithfulness 有陈述提取和证据判断，F1 有双向事实验证，重试也需要计数。
- 请求前预留额度，失败/取消不返还模糊用量；断点恢复不重置已用额度。
- 未测/评分错误为 null，不用 0 混淆“缺失”与“真的答错”。本次 Baseline 的 0 是真实框架评分，而不是补值。
- completed 是应用终止状态，事实正确性、证据支持和引用语义是不同维度，不做随意加权总分。
- 单题只支持校准发现，不做置信区间或显著性结论；同题重复不能冒充更多独立题。
- 存储真实 usage，不拿字数估计冒充实测 Token，也不在缺少价表时声称真实费用。

未完成的公开评测、记忆收益、人工一致性和商业产品比较，要说明它们尚未验证，不能当作已有项目成果。

## 新增面试追问：如何证明记忆不是上下文拼接？

每个 episode 使用独立 SQLite，写入走应用的显式偏好或研究 consolidation，召回探针使用新 thread，并检查原会话消息为空。然后保存实际版本/status、召回 ID 和模型输入，再做相同场景的 memory off 对照。7 个指定正向目标实测 on 命中 7/7、off 为 0/7；到期、删除与隔离探针没有召回禁用内容。

这证明的是受控输入下的存储与召回链路，不是模型质量提升。我也检查当前用户请求优先规则进入了模型，但不会据此宣称模型真的服从；真实偏好服从度、语义召回与记忆对回答质量的收益尚未验证。见 [续建报告](../evaluation/benchmark-continuation-20261002.md)。

## 新增面试追问：为什么 Baseline 分数为 0，还不能说显著提升？

因为只有一对开发校准题，且 Baseline 生成失败，0 来自裁判实际评过的兜底文本。我的分析保留这项失败：all-output 可以给观察差值，但区间为 null；completed-only 没有完整对照对，不能拿 Harness 的单独成功替代公平比较。同题重复必须先聚合，不能膨胀有效题数，评分缺失也不能补成 0。

## 新增面试追问：30 道题是怎么来的，可信吗？

固定官方文档提交和原始文件字节，编写六类能力共 30 题，12/18 按来源组切分。每题有成功要求、参考答案和可定位的逐字来源，合计 47 处引用；加载时检查来源/许可哈希、引用行号及切分。评分侧的 gold 和审查字段不进入检索正文，改变参考答案也不改变实际基线回答与轨迹。

但我不会说这是人工金标准：目前是 Agent source check，human_reviewed=0；同发布方概念仍重叠。真实资料题、人工审查、真实模型实测是三件事。公开 DRB 的 5 题已保留原文并冻结选择理由，没有参考答案、未跑实时研究，更没有官方榜单分数。详见 [数据治理报告](../evaluation/governed-assets-20261002.md)。

简历可补充：“构建 30 道真实官方资料题与 5 道公开任务的版本化评测资产，实现来源/许可/切分治理、参考隔离与实验身份绑定。”不要把“构建资产”改写成“已完成 35 题真实 API 测评”。

## 新增面试追问：评测如何指导改进，而不是只输出一个分？

我会追踪证据从抓取、完整存储、research outcome 到回答模型输入的每一层。3 道预选开发题的 6 个脚本诊断中，10 处片段-运行检查有 2 处没有抓取，8 处已存储且选用却没有完整送达 responder。固定前缀摘录和检索覆盖是两种不同问题，不能都解释成预算不足，更不能把 completed 当答对。

这一结果是字面片段送达检查，不是 0% 正确率；裁判看到全文也不说明 Agent 看过全文。我还修正了指标大小判断：事实 F1 不因未使用的长证据被禁用，Faithfulness 不因未使用的 gold 被禁用，真实超限仍为 N/A，缓存身份随 adapter 更新。

CI 已配置独立评分环境和禁网测试，但本机 Docker/远端尚未跑过，不能写“线上 CI 已通过”。详见 [诊断与 CI 报告](../evaluation/ci-long-context-20261002.md)。

后续我实现了两系统共享的问题相关选段，不扩大原预算、不新增模型调用、不读取 gold。保留来源行号/字符位置，并区分选段与 token 再次裁剪。在相同 3 道开发题的复测中，10 次片段-运行检查的完整可见数从 0 到 2；仍有 6 次未完整覆盖、2 次来源未抓取。这说明修复了固定前缀的一个限制，不是已经解决全部长文问题，也不是答案质量提高 20%。真实抓取还有默认 2 万字符前缀上限，回答选段无法找回这一步丢失的内容。见 [实现与复测报告](../evaluation/query-excerpts-20261002.md)。

可补充的简历表述：“建立抓取—存储—回答输入的证据送达诊断，实现 Baseline/Harness 共用的有界问题选段与来源位置追踪，通过真实生产回答图的尾部事实、预算裁剪和参考隔离回归。”不要写成“真实长文端到端全通过”或“超过成熟 DeepResearch”。
