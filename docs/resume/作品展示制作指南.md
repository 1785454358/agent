# 作品展示制作指南

这个项目可以作为后端与 Agent 工程方向的作品。仓库负责证明代码和测试存在，90 秒视频负责证明系统能跑，架构图负责让面试官在很短时间内抓住设计重点。三份材料要讲同一个项目，名称、三种研究模式和存储分工都保持一致。

## GitHub 仓库怎样整理

面试官打开首页后，前半分钟应当看到项目解决什么问题、三种模式怎样区分、Harness 管理哪些公共能力，以及怎样启动演示。

提交前完成下面的检查。

- README 首屏保留一句项目定位、一张总体架构图和三种模式表。
- 快速开始同时提供 Local 与 Distributed，两套命令都亲自从干净环境走一遍。
- `.env.example` 只保留占位值，使用 `git grep` 检查 Key、Cookie、内网地址和个人信息。
- 仓库保留测试目录、Alembic 迁移、Docker Compose 和面试学习文档。
- 删除临时日志、旧设计入口、无用途脚本和本地运行产物。
- GitHub Actions 执行非真实测试，README 放置 CI 状态徽章可以等工作流首次成功后再加。
- 许可证需要由作者按公开意图选择。确定开源前再加入 MIT、Apache-2.0 或其他许可证，不要默认替自己作法律决定。

推荐的首页阅读顺序如下。

```text
项目定位
总体架构图
三种研究模式
记忆与可靠性亮点
本地和 Docker 快速开始
API 示例
测试方式
深入文档入口
```

## 90 秒演示怎样录

先把演示完整跑两遍，再开始录屏。浏览器只保留项目页面，终端字号调大，关闭通知。视频使用 1080p 即可，鼠标移动保持慢而明确。每一段只证明一件事。

| 时间 | 画面 | 口播重点 |
| --- | --- | --- |
| 0 至 10 秒 | README 总体架构图 | 这是一个基于 LangGraph 的多模式深度研究 Agent，统一 Harness 管理工具、记忆、证据和恢复 |
| 10 至 25 秒 | Web 页选择 Plan-and-Execute 并提交问题 | 三种策略共享运行协议，这次用有界重规划处理多步骤问题 |
| 25 至 45 秒 | 实时事件与最终普通回答 | 展示规划、检索、证据引用和默认 Answer，避免等待时长全部录进去 |
| 45 至 58 秒 | 点开一个引用或展示 Evidence 来源 | 回答只能引用本轮允许的 Evidence，正文没有塞进 Graph State |
| 58 至 72 秒 | 保存一条偏好，再开新 thread 发起相关研究 | MySQL 先过滤作用域，BGE-M3 与 Chroma 做候选内 TopK，命中后回查 MySQL |
| 72 至 83 秒 | 终端展示测试结果和 Docker 服务 | MySQL、Redis、Chroma、API、Worker 分工，以及自动化测试数量 |
| 83 至 90 秒 | 回到架构图 | 收束到 Harness、三种策略、可靠工具调用和可恢复执行 |

可以剪掉模型和网络等待，只保留提交、事件推进和结果出现。画面角落标注“等待已剪辑”，避免让人误以为响应是预生成的。不要在视频里展示 `.env`、完整请求头或数据库密码。

口播可以从下面这段开始练，录制时用自己的语气复述。

> 这是我独立开发的多模式深度研究 Agent。项目用 LangGraph 实现统一 Agent Harness，把上下文、工具、证据、记忆和恢复放在公共运行层，Workflow、Plan-and-Execute 和 Multi-Agent 只负责各自的研究策略。这里我选择 Plan-and-Execute 提交一个多步骤问题，可以看到任务规划、检索事件和带来源的普通回答。网页正文进入 Evidence Store，图状态只保存 Evidence ID。长期记忆由 MySQL 保存权威记录，本地 BGE-M3 和 Chroma 完成候选内语义检索，结果仍要回查 MySQL。分布式环境由 Redis Streams 投递任务，Checkpoint 与工具账本共同处理恢复和重复调用。

录完后实际计时。超过 90 秒时优先删等待画面和重复口播，不加速到难以听清。

## 架构图怎样制作

README 中的 Mermaid 图是文字版本的权威来源。作品展示再导出一张 16 比 9 的静态图，放在仓库 `docs/assets`，用于视频封面、简历作品链接和面试共享屏幕。

图上只保留四层。

1. 入口层包含 Web、API 与 Application Service。
2. 编排层包含顶层运行图、三种策略子图和响应子图。
3. 治理层包含 Model Gateway、Tool Gateway、预算、Ledger、Evidence 与 Memory。
4. 基础设施层包含 MySQL、Redis、Chroma、BGE-M3 和外部搜索服务。

颜色只表达所有权。编排层使用一种颜色，公共治理使用一种颜色，数据存储使用一种颜色。箭头上的文字只写关键对象，例如 `ResearchInput`、`ToolRequest`、`Evidence ID` 和 `memory_id`。不要把每个 Python 文件都塞进总图，源码目录图另放在面试材料中。

导出后检查三个问题。

- 缩小到简历作品卡片大小后还能读清模块名。
- 面试官能沿着一次请求从入口走到回答。
- MySQL、Chroma 与 Redis 的职责没有画混。

## 发布前演练

从一个没有项目缓存的终端执行下面的命令。

```powershell
cd backend
uv sync --frozen
uv run pytest -m "not real"
cd ..
docker compose --env-file .env.docker config --quiet
```

随后启动 Docker，完成一次普通回答、一次报告请求、一次长期记忆跨 thread 召回和一次服务重启后的任务查询。把实际测试日期、命令和结果写进 Release 说明。作品页只写已经亲自验证的能力。

## 面试现场怎样使用

先用架构图讲 30 秒，再打开视频或现场页面。对方追问具体实现时，按模块跳到源码。

- 顶层生命周期打开 `harness/graph.py`。
- 三种执行策略打开 `strategies` 下对应的 `graph.py`。
- 工具安全与预算打开 `tools/gateway.py`。
- 恢复边界打开 `persistence/checkpoint.py` 与 `persistence/execution_ledger.py`。
- 长期记忆打开 `harness/memory/retriever.py`、`persistence/memory_store.py` 和 `persistence/chroma_memory.py`。

展示代码时先说这个模块解决的问题，再指向一个主要函数，最后说明失败边界。这样比逐行念代码更容易让面试官确认你真的理解设计。
