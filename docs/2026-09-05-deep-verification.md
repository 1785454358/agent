## 最新真实模型冒烟

使用当前本地模型配置执行 `bench_deep.py`，题目为读取 `https://react-lm.github.io/` 并概述核心机制与一项局限。测试限制为最多两项任务、六轮执行、一轮重规划、三次研究工具调用，不设置总时长、累计 Token 或费用预算。

| 指标 | 结果 |
| --- | --- |
| 终态 | completed，无 Writer 降级 |
| 研究运行耗时 | 41.6 秒 |
| 含初始化及清理 | 49.016 秒 |
| 研究工具调用 | 1 次网页读取 |
| Planner Token | 1,092 |
| Executor Token | 3,949 |
| Replanner Token | 2,085 |
| Writer Token | 2,568 |
| 总 Token | 9,694 |

报告使用数字标题、正文 `[1]` 引用、文末 URL。本地完整输出位于 `backend/runs/deep-smoke-count-only.json`，运行产物不纳入 Git。

此前使用临时总时长限制的短题冒烟为 33.8 秒、8,504 Token；开放搜索题曾在 90 秒内无法充分完成并发生 Writer 降级。它们属于旧策略探索结果，不能作为新版性能承诺。最新版本已取消总时长、Token、费用停止条件。

## 当前限制及待办

- 子任务按依赖顺序执行；每轮最多三个独立研究工具并行，并非多 Agent 并行调度。
- 长期语义资料记忆需开启 `DEEPTRACE_USE_MEMORY`；工作记忆始终启用。
- 累计时间与 Token 仅用于观测。单次请求仍有故障超时；Provider 未返回的 Token 无法准确统计。
- 达到次数上限仍由 Writer 生成现有资料报告，未解决问题会标记 partial。来源质量、结论完整性以及严格字数遵循尚需多题评测，短题冒烟不等于研究质量验收。
- 自动重启被当前执行策略拦截，8000 端口仍是旧后端进程。需停止旧服务后，在 `backend` 下运行 `uv run python -m deeptrace.api`，再刷新页面测试新版 Deep 模式。
