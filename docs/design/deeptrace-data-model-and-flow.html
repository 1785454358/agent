DeepTrace MVP · 数据模型与运行数据流

设计目标：把“模型说了什么”变成“系统能够证明什么”，并保证每一步都可恢复、可评测、可追溯。

1. 核心数据模型

第一版使用 PostgreSQL；向量字段由 pgvector 承载

ResearchRun · 一次研究

  • 原始问题与结构化 ResearchBrief
  • 状态、轮次、预算、当前阶段
  • 父运行 ID，用于“更新研究”
  • Checkpoint 与统计指标

ResearchTask · 子任务

  • 研究问题与完成标准
  • 优先级、状态、负责人
  • 搜索查询历史
  • 覆盖分数与失败原因

Source · 原始来源

  • 规范化 URL 与内容哈希
  • 标题、作者、发布时间、抓取时间
  • 来源类型与域名质量
  • 正文快照和抓取状态

Evidence · 可引用证据

  • 来源中的原文片段与定位信息
  • 提取摘要、所属子任务
  • 时效范围与提取置信度
  • 内容向量，用于研究记忆

Claim · 待验证结论

  • 最小可验证陈述
  • 重要性与时间敏感性
  • verified / disputed / insufficient
  • 综合置信度

ClaimEvidence · 证据关系

  • Claim 与 Evidence 多对多连接
  • supports / refutes / context
  • 语义支持分与 Verifier 理由
  • 是否允许进入最终报告

Report · 研究报告

  • Markdown 正文和结构化摘要
  • 引用映射与报告版本
  • 覆盖率、引用率、成本与耗时
  • 关联的已验证 Claim 集合

RunEvent · 运行事件

  • Agent、Tool、阶段和事件类型
  • 开始/结束时间、Token、费用
  • 错误码与重试次数
  • 面向 UI 的安全摘要
ResearchRun 1→N ResearchTask · Task N↔N Source · Source 1→N Evidence · Claim N↔N Evidence · Run 1→N Report / RunEvent

2. 一次完整研究的数据流

每个步骤都有结构化输入输出，可单测并可从 Checkpoint 恢复
创建 ResearchRun解析问题，生成 ResearchBrief、预算和来源偏好。
Planner 创建 Tasks拆解 3–6 个子任务，为每项写清完成标准。
Researcher 并行执行先搜候选来源，再读取正文；不把搜索摘要当证据。
落库 Source / EvidenceURL 与内容哈希去重，保存原文片段和时间元数据。
生成原子 Claim把长段总结拆成可独立验证的最小事实陈述。
Verifier 建立关系判断支持、反驳或仅提供背景，并标记不确定性。
Gap Controller 决策计算覆盖缺口；有预算则生成补充 Task，最多第二轮。
Writer 生成 Report只读取允许发布的 Claim 和 Evidence，写出行内引用。
核心不变量
Report Writer 不能读取原始搜索结果，也不能凭聊天上下文补充事实；可进入报告的外部事实必须存在 Claim → ClaimEvidence → Evidence → Source 路径。
Memory 的实现
历史 Evidence 与 Claim 本身就是研究记忆。相似任务先召回，再按发布时间和内容哈希判断“复用、重新验证或失效”，第一版不额外创建抽象的 Memory 表。
