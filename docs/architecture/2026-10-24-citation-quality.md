# 引用审查与逐句评分修复（2026-10-24）

本轮继续改善回答的证据准确性。发现的实际问题是：简答和正式报告跳过了最终事实审查；部分直接追问也没有进入审查；独立引用评测只检查同一来源首次出现的句子，且静默截断长句与来源正文，可能遗漏后续误引和限定条件。

## 交付行为

- `responses/graph.py` 将已有的单次审查覆盖到 answer、brief、report 和带来源的直接追问。保留原有回答形式、分节、有效建议和适用范围，审查不通过仍明确返回 partial。
- `BudgetAllocation.rendered_segments` 保存本次实际装配的文本。审查只接收写作模型实际看见的来源段，包含预算截断后的原文及原编号；预算事件的 `summary()` 不记录这些正文。
- 写作预算预留审查指令和草稿空间，审查前继续检查完整输入预算。未扩大模型窗口、共享调用预算或共享输入预算；来源全部被预算淘汰时不发送空证据审查。
- 审查逐次核对同一编号的引用，纠正来源对调、范围扩大，以及将理论或模拟写成物理实验。报告沿用自身篇幅上限，审查 schema 支持最多 50,000 字符，不再被短答案的 8,000 字符上限误拒绝。控制字符和来源外编号仍拒绝。

默认模型、思考开关和研究轮次没有变更。新增审查会增加原先跳过它的路径的调用与耗时，仍受原预算约束。

## 独立评测修复

`backend/evaluation/claims_quality.py` 保持标准库实现，不导入生产代码，继续在独立环境运行。版本从 `claims-v1` 更新为 `claims-v2`，缓存随版本失效。

引用准确性的单位改为每个“句子、来源编号”使用点：同一来源在不同句子出现时分别判断；同一句重复同一编号不重复计数。Markdown 行内代码、反引号和波浪线围栏中的数组下标不作为引用。

不再将句子截成 300 字符、来源正文截成 6,000 字符。超过 2,000 字符的引用句、超过 100,000 字符的完整评审输入返回未测量原因，避免只评被截断的一半。保留有限调用采样，输出 `citation_use_count`、`checked_citation_count`、`citations_truncated` 和 `score_scope`，明确区分全部检查与采样检查。

这改变了独立评测的计分口径，不能把 claims-v1 与 claims-v2 的数值直接当作同口径质量提升。下方六题对照使用原来的 `AnswerQuality` 评审 schema，不是这一独立引用分数。

## 真实模型对照

固定原文和六道开发题，沿用上一轮的参考答案、覆盖要求、同模型盲评和关闭思考配置；本轮写作探针显式打开最终审查。结果如下，分值为 1–5：

| 指标 | 上轮未审查写作探针 | 本轮含审查写作探针 |
|---|---:|---:|
| 引用准确性 | 4.17 | 4.33 |
| 证据支持 | 4.17 | 4.33 |
| 解释深度 | 4.17 | 4.33 |
| 可读性 | 5.00 | 5.00 |
| 需求覆盖评分 | 100% | 100% |

六题均有配对评分，无生成错误、评审错误或 partial。本轮 18 次提供方调用分别为六次草稿、六次审查、六次评审。六题写作阶段累计耗时从 14.372 秒变为 39.941 秒；本轮时间包含审查，前次不包含，不能解释为所有生产回答统一变慢这个比例，普通 answer 原先就有审查。

这是六道用于开发的题、每题一次采样和同模型评审，没有独立人工裁决或留出集。结果仅表明本次固定材料对照小幅改善，不能证明普遍准确率、检索质量或相对商业产品的优劣，也不是将审查效果与所有装配变化完全分离的因果实验。
