# 有界的任务完成闭环

本轮实施以用户授权的“方案—取证—一致性”方向为基础，不增加独立 Agent 或每轮额外模型调用。

1. 复用补查调用：同时决定是否修订交付方案，附修订原因及已验收 finding 引用；宿主验证需求集合、引用及结构。保留原始合同和历史，修订不是事实覆盖。
2. 统一控制器允许最多三轮研究；每次必须有新的查询或尚未执行的原文读取。无进展信息交给恢复规划，不能仅因第一次失败就结束，也不能无限重试。全局预算与响应预留继续优先。
3. 预算区分所选主线费用和未选可选费用。可选项目保留展示但不计入所选预算，不因其价格未知产生必需费用缺口。必需项目不能为通过检查而改成可选。
4. 规划强调用户所有交付维度，可合并同类事实需求；补查利用具体失败阶段和原文导航，避免机械换词。
5. 已授权原文中的实际链接可以进入下轮候选（最多两条，按链接所在行与任务的相关性筛选），复用来源选择、授权抓取和原文阅读。搜索无结果时仍可沿已知文档取证；冻结资料集不向外导航。链接和摘要始终不是事实证据。
6. 区分月度额度耗尽与普通429限流。明确额度耗尽时停止本次运行后续模型派发，持久化阻碍；新运行可以重新尝试。答复明确恢复条件，不把服务不可用写成资料不存在。

验证采用先失败的回归测试，覆盖方案修订、需求不可删除、未授权引用、重复读取、第三轮获得证据、预算范围。随后运行全套测试及真实跨领域任务。默认入口切换 controller，使三种公开模式都使用统一调度；显式 legacy 配置继续兼容。共享补查与预算改进也覆盖旧入口。

不能保证外部数据、权限或任务本身总能满足。研究 coverage 与可交付建议仍分开：估算和建议不冒充已核实事实，无法完成时保留实际阻碍。
