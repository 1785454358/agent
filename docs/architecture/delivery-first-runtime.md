# 当前研究主干：有限收集后交付报告

2026-11-19。实施依据：[已授权的减法设计](2026-11-19-delivery-first-research.md)。

## 生产流程

```text
原始问题 → 自动路由/手动模式 → 一次短计划 → 有限搜索与阅读
        → 实际原文写报告 → 必要检查/至多一次就地修订 → 交付
```

`research/runtime.py` 只保留 `plan → dispatch → execute_task → finalize` 四个研究节点。每个计划任务至多调度一次，最多六个；并行模式按批次汇合，失败分支不会清空成功分支的材料。没有逐轮 evaluator、recovery、reread、field recovery 或 replan 节点。

三种模式使用同一图构建器：

| 模式 | 当前差异 |
|---|---|
| Workflow | 固定顺序逐项收集，任务之间不累积授予新来源 |
| Plan-and-Execute | 逐项收集，后续任务可以复用此前已取得并重新授权的来源 |
| Multi-Agent | 独立任务有界并行收集，随后统一写作 |

`auto` 的动态路由及手动覆盖保留。三种模式都直接收到原始问题与用户约束。配置 `research_orchestrator` 的三个旧名称均指向这一个实现；切换配置不会重新启用旧算法。旧的 `max_rounds`、`max_replans`、`max_follow_ups` 形参只保留调用兼容性，不触发额外研究轮次。

## 实际移除的职责

- 生产退出不再要求所有事实 `covered`，不再生成研究 verification 结果。
- 不再执行 full/delta/reused 核验账本、评估快照保留、计划审查与按缺口重规划。
- Controller 检查点通道由继承后 **54 个降到 23 个**，不再携带 coverage、计划历史、补洞动作和 task-results 调度账本。
- 三个旧策略图工厂合并为共同主干的入口；旧的独立编排不再注册到生产。
- 新研究结果的 writer 不走旧 witness/checks/edits 多阶段协议；普通问题一次写作，必要时直接返回一次完整修订正文。
- 新材料不会在写作时再次按关键词裁成另一份摘要，reviewer 使用 writer 实际获配的同一份来源文本。

历史 DTO、离线核验函数以及它们仍有意义的单元测试保留。相关模块还存在，不代表生产循环仍执行它们；本轮没有宣称仓库中所有历史算法文件都已删除。直接回答/历史兼容路径也仍保留原响应处理，当前简化写作出口用于 `delivery_first=True` 的研究结果。

## 保留下来的底座

沿用 EvidenceStore、URL/来源权限、工具执行账本、缓存、共享模型与工具预算、usage 和持久化检查点。保留写作预留额度，不在研究预算耗尽后继续开全局核验循环。

`ResearchOutcome.read_anchors` 交接实际工具读取的字符范围。写作前检查 evidence ID、version、content hash、坐标和当前正文 SHA-256，禁止用过期/被篡改材料。公共 token 分配器只装配一次写作视图；有效引用须来自其中实际可见的阅读片段。读取不等于认定来源正确或该结论已核实。

权限拒绝、取消（包括子图 `NodeCancelledError`）、预算存储故障向上传播。普通网页/分支失败记入限制。没有可用正文、写作失败或有效正文无法修订时，给明确的有限结果，不将异常字符串当成成功报告。可选审查不可用时保留已有有效正文，同时标记 `answer_review_unavailable`，不会伪称已审查。

原始阅读不自动升级为“已验证事实”写进记忆；已有记忆检索与事实存储仍保留。

## 状态与迁移

新 turn 写入 `research_flow_version=2`；新研究结果标记 `delivery_first=True`。新报告有有效正文和引用、无输出故障时可以 `completed`，依据充分性仍单独投影为 `unknown` 或 `insufficient`。历史结果默认 `delivery_first=False`，保持原完成语义，不批量重标。

同线程新运行会重置前次收集结果；同一新运行中断后按检查点恢复，已经完成的并行分支不重复执行。旧版未结束运行明确拒绝由新算法直接恢复：使用冻结的原版本继续，或创建新 run；不要清空工具账本伪造恢复。

## 验证与已知限制

参见[实测与测试迁移记录](../benchmarks/2026-11-19-delivery-first.md)。新测试覆盖三模式真实调度差异、失败隔离、预算到限、权限/取消传播、SQLite 重启恢复、同线程新任务隔离、原文尾部交接、版本/hash 失效及审查失败保留正文。

本次收缩解决“局部缺口阻断整篇报告”和重复核验成本，不保证规划永不漏题、检索一定选全来源或正文每条结论都正确。跨语言实测仍有 Go 调度/取消资料采集不足；后续应针对取材质量处理，不重新引入全量覆盖与恢复体系。
