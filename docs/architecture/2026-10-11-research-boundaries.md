# 研究未完成的根因与边界修复

更新：2026-10-11。本轮延续 [前序完成与取材优化](2026-10-11-research-completion.md)，保留此前所有运行记录。

当前证据首先指向本项目的上下文传递、核验协议和完成判断。搜索与抓页也会影响资料覆盖，但不能把已找到原文后的误判归因于搜索服务。没有更换 Tavily，也没有增加模型预算或补查轮次。

## 根因与证据

| 层次 | 发现 | 影响与修复 |
| --- | --- | --- |
| 分支上下文 | Workflow、Multi 的父节点与分支节点各投影一次上下文；第二次只读取全局 brief，忽略已投影的域名、科研模式、年份与互补查询。私有 State 也未声明这些字段 | 计划限定官网，执行搜索却失去域名过滤。共用 ResearchBranchContext，投影保留私有字段且允许根计划显式空值覆盖。真实图派发回归修复前 Workflow、Multi 失败，顺序 Plan 通过；修复后全部通过 |
| 规划降级 | 任务名与映射不一致时，全局来源简报也被丢弃 | 分开校验全局简报与任务映射，降级撤销分支分工，保留有效域名／年份；无效简报、权限／预算等额外字段仍拒绝 |
| 引用协议 | 原文阅读组被拆成最多 500 字符的引用，模型每条 finding 却只能选择 3 个短引用 | 旧量子运行第 5、6、10 次核验因 supports 过多未通过 schema。新增当前视图的 g 阅读组引用，宿主展开为原文 p 引用；模型入口仍最多 3 项，日期仍用精确 p 引用 |
| 核验范围 | 规划建议进入核验输入；年度规划指令同时要求默认按发表年和额外查实验完成日期 | 核验出现语言限制扩大、要求原文直接给比较句、或条件被变为且条件、未问的内部机制被变成缺口。核验只保留原任务、用户约束、封存需求和当前原文；规划建议继续供取材使用 |
| 最终交付 | 一条研究核验标为全部覆盖，事实审查却删除某用户要点的无证据推断，终态仍 completed | 事实审查协议必须返回 unanswered_points；真实缺口投影为 answer_review_incomplete。Workflow 仍以固定流程结束为完成，质量缺口独立记录；Plan/Multi 保留部分交付 |
| 补查输入 | 阅读组展开后的原文被每条结论重复携带到补查规划 | 规划只需要已支持的结论、来源 ID 和缺口，移除重复原文；完整引用保留在领域记录，实际核验继续读取原文。固定回归从 13847 输入 token 降至 3500 以下，没有加预算 |
| 搜索／抓取 | 旧、新运行均能发现官方文档及原创论文；仍观察到正文不足、抓页超时、日期原文缺失和窗口省略 | 搜索结果、已抓正文、核验实际可见原文逐层区分。当前没有同条件搜索供应商对照，不能声称换 API 就解决，也不能断言召回已经足够 |

这属于本项目对 Harness 边界的实现问题，不能据此认定 LangGraph 本身不适合。官方文档说明节点输入和私有状态可以具有不同 schema；字段穿过边界时需要由应用明确传递。[LangGraph Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)。Pi 的 Agent Core 将持久消息与模型输入转换分开；本项目借鉴明确上下文边界的方式，继续使用现有 Gateway 与 LangGraph。[Pi Agent Core](https://raw.githubusercontent.com/earendil-works/pi/main/packages/agent/README.md)。这些参考没有被作为完成质量或性能背书。

## 实现范围

- 新增一个共享分支上下文类型，沿用现有策略和 Gateway；没有新增调度框架、角色或搜索供应商。
- 阅读组只能引用最终预算窗口内的原文。未知组、隐藏组、缺少成员、混合版本组拒绝；原文版本、哈希、坐标、来源准入和科研日期门禁保留。
- 宿主 Finding 的引用保存上限从 5 对齐到当前视图的 128 个短引用，供阅读组展开使用。模型仍只能选择 3 个入口；8 个来源、128 个可见短引用、全局 token 窗口不变。这是保存协议变化，不能称为完全未调整引用容量。
- 原有 20 次模型调用、100000 输入 token、最多两轮补查和收尾预留保持不变。没有将 partial 直接改成 completed。
- 被拒绝的冗余科研 finding 仍写诊断；若其他合法成果已经覆盖全部需求，不再凭这条拒绝额外生成一个泛化的“需要成果日期”未决问题。

## 控制重放

固定旧模型核验可见的原文片段，按来源重新 ingest，并按阅读组保留未读间隔；使用当前 deepseek-v4.1-flash 调用真实 evaluator，再执行宿主引用、来源和日期准入。没有搜索或抓页，也没有写最终回答。重新 ingest 后的坐标对应片段正文，不冒充旧生产全文的坐标。

三个探针各调用一次模型：

| 冻结材料 | 修复前现象 | 当前宿主覆盖 | 含义 |
| --- | --- | --- | --- |
| Python 同题 Multi，旧第 8 次核验 | 4/5，新增内部机制要求 | 5/5 | 同一批已有原文可以回答封存需求；补搜不是该次误拒绝的必要解法 |
| Python 跨文档 Multi，旧第 9 次核验 | 前一轮系统规则重放 2/3，要求直接比较句 | 3/3 | 可由分别支持的事实形成有界比较；仍需独立检查答案是否过度概括 |
| 量子 Plan，旧第 5 次核验 | 引用过多，schema 失败 | 1/4 | 当前 schema 成功；模型提出的成果仍因原文日期／成果准入被宿主拒绝，不能把格式修复当作全部完成 |

三个探针通过片段正文 quote 与来源准入核对；不作为端到端成功率、准确率或速度比较。

## 中间失败与质量边界

第一轮阅读组实现漏调了领域 Finding 的旧 5 项保存限制，真实运行出现 ValidationError。失败样本保留；新增超过 5 项展开、完整 evaluator 覆盖及序列化回归后修复。初始测试只用了 5 个短段，未跨过领域上限，是测试设计遗漏。

之后一条 Plan 8bf8d57172b0 在 42.629 秒、6 次调用、25707 总 token 下显示 completed，覆盖 6/6；事实审查却删除了吞掉 CancelledError 的具体影响并说明缺证据。这条记录是完成判断的反例，不作为质量通过。后续新增明确未回答要点门禁并重新跑生产路径。

中间量子样本 2e183e5b4c5d 为 partial／max_replans_reached，208.613 秒、15 次调用、83553 总 token；它是事实审查缺口门禁加入前的阶段记录，不代替最终运行。所有失败、阶段成功和最终重跑分别保存。

机械引用正确、模型判 covered、答案实质回答是三个检查。当前仍缺少稳定的语义反例评测集和同条件供应商对照；单次 completed 不能证明所有事实正确，开放领域综述也不保证全部完成。

## 对 Harness 岗位的可讲内容

可讲的工程经验是：从轨迹区分发现、抓取、阅读、协议和语义问题；将失败材料冻结以排除搜索变化；用真实分支回归验证上下文传递；让事实审查结果进入运行终态。新增功能集中在原有边界，避免靠增加角色、预算和无限补搜掩盖缺陷。个人贡献按实际参与说明，不把代码存在等同独立完成。
