# 真实任务质量优化：实施与验收

依据北京 3 天 2 晚实测及用户已确认的优化方向实施。本轮不增加编排层、搜索提供商或额外常驻评审 Agent；使用同模型、同额度、同题重测。

1. 规划：缩短通用提示，科研规则仅作为条件规则；controller 的元数据错误局部降级，保留已验证查询和原始用户约束。legacy 保留原行为作对照。
2. 取材：使默认任务页数与现有三来源目标一致；不增加 run 的调用、token、时间总额度。
3. 验证：将来源拒绝依据绑定到真实用户限制；普通价格参考允许有日期和条件的非官方材料。显式记录复合需求尚未支持的子项，宿主禁止将存在缺项的需求标记为 covered。
4. 补查与成稿：提示优先补齐影响最终交付的独立缺口；允许明确假设下的预算分配和建议，市场实价仍须有依据；避免用大额机动占位代替预算。
5. 先写失败回归，再实现；全量后端通过后，保存新一次真实试验的独立目录、原始回答、用量及诊断，保留失败的基线。

来源资格和语义支持仍含模型判断，结构约束不能保证所有语义判断正确。最终验收必须检查实际答案，不能只检查 completed。

## 实施补充

- 通用规划提示已缩短；controller 在可选简报/映射错误时保留独立合法的查询，legacy 降级语义维持原样。
- 默认发现任务最多读取 3 页；不是新增模型调用或扩大全局预算。
- 来源判断显式说明拒绝依据；声称用户限定来源时须提供可匹配原始用户文本的引文，否则标为 uncertain 并触发有限修复。
- 复合需求增加 `unanswered_parts`，存在缺项时宿主不接受 covered；这仍依赖模型识别缺项，不等于自动证明完整性。
- 首轮优化真实测试未通过：9 次调用、87,934 输入 token，最终审查超出剩余额度后仅返回来源列表。该次记录保留在质量对比目录的 attempt-1。
- 针对此失败，补充研究原文导航从最多 128 条缩为缺口相关优先的 24 条，去掉重复网址/标题；剩余额度快照用于评估与写作的完整材料选择，实际准入仍由同一持久化预算网关执行。
- 第二次真实测试进一步暴露两处错误，已回归修复：分支模型调用达到局部上限后，误禁止不需要模型的抓取/阅读；输入额度快照又重复扣除了模型输出预留。局部模型调用仍由 invoke 拒绝超额，全局预算仍可停止采集；模型窗口与运行输入额度分别计算。
- 审查因模型额度或供应商调用失败而不可用时，保留已通过后续引用校验的草稿并明确标注未经最终事实审查，状态保持 partial。审查返回非法结构或控制字符仍拒绝该结果，不将其当成已审查内容。
- 第三次已生成行程和完成审查，但五次评估耗用 53,309 输入 token，仍挤占有效材料。评估修复进一步收敛：宿主直接删除与 covered 判断无关的不合格发现，重新归一覆盖；只有 rejected 发现影响 covered 判断，或存在未经授权的来源限制时，才消耗既有修复机会。未放宽来源和证据条件。
- 第四次发现 Writer 的额外页面选段挤出已接受的天坛票价证据。运行输入额度比模型窗口更紧时，Writer 改为保留已验证引用、原有邻近段落及边界上下文，不再附加查询命中的额外页面内容；不按字符盲截已验证引用。未受运行窗口限制的原有选段行为保留。此项失败回归及相关检查 130 passed，并做第五次独立真实试验。

确定性验证命令：在 backend 目录执行 `.venv/Scripts/python -m pytest -q -m 'not real'`。末轮完整检查 1618 passed，1 deselected，33 warnings，124.85 秒。另完成五次独立真实试验并保留全部失败记录；末轮 81.27 秒、12 次模型尝试、85,725 输入 token、7 个引用 URL，写作及审查完成且未丢弃来源，但仍为 partial / insufficient_evidence。可用草案与事实核实合格是两回事，本次完整事实验收仍未通过。详情见 [对比记录](../benchmarks/2026-11-15-beijing-quality-optimization/README.md)。
