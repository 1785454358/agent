**结论：主线选开源自托管 Uptime Kuma，部署在现有闲置 Linux 服务器上。** 20 个 HTTPS 站点、故障通知、历史累积均可在自托管内实现；软件许可 0 元，服务器为既有资源，新增现金支出主要是域名（若已有则为 0），按年价折算后远低于 300 元/月。通知渠道的免费额度与速率限制本次材料未给出，标为未核实。

## 一、选定方案与依据

- **监控能力**：HTTP(s) 监控器会请求目标 URL、测响应时间、读状态码，并默认读取 SSL 证书、记录到期日期与证书链，适合 HTTPS 站点及证书到期检查 [1]。
- **检查频率**：间隔、超时、重试可按监控项配置；官方指南给的实用起点是 **60 秒间隔、30 秒超时、2 次重试**，再按误报率调整 [1]。仓库功能列表写有“20-second intervals” [2]，但**最小允许间隔的具体数值原文未明确**，本方案按 60 秒设计，不依赖 20 秒下限。
- **历史保留**：监控项、通知设置和正常运行历史保存在 `/app/data` 的 SQLite 数据库；自托管必须把该路径挂载到持久卷或本地目录，否则重部署会丢历史 [3][2]。**原文未给出“保留 30 天”的专门配置项或自动清理机制**，历史能否覆盖 30 天取决于持久化存储与实例持续运行，需上线后实际观察。
- **通知渠道**：支持 90+ 提供商，包括 Telegram、SMTP 邮件、Slack、Discord、Webhook 等，在 Settings → Notifications 配置，可绑定单个监控项或设为默认 [3][2]。
- **部署方式**：Docker 单容器（映射 3001 端口、挂载 `/app/data`），或 Node.js（>=20.4）+ Git + PM2 源码运行；官方明确**不支持 NFS 类文件系统**，需映射本地目录或卷 [2]。

## 二、检查频率与通知设计

- 20 个站点各 1 个 HTTP(s) 监控，60 秒间隔、30 秒超时、2 次重试 [1]。
- 通知主线选 **SMTP 邮件**（团队已有邮箱即可，配置门槛低），备用可加 Telegram 或 Webhook [3][2]。
- **未核实项**：Telegram Bot 与 SMTP 服务的具体免费额度、速率限制，本次材料未披露；因此“20 个站点故障通知量是否被免费额度覆盖”无法从材料确认，需在选定服务商后查其官方限额。按 20 站点、偶发故障估算，通知量通常很小，但这只是推断，不是已核实事实。
- **5 人查看**：通过同一面板查看告警与历史；原文未说明多用户权限或 SLA，本方案不假设多租户能力。

## 四、部署步骤

1. 在闲置 Linux 服务器安装 Docker 与 Docker Compose（Debian/Ubuntu 等主流发行版受支持 [2]）。
2. 创建本地目录并启动容器，挂载持久化路径：

```bash
mkdir -p /opt/uptime-kuma-data
docker run -d --restart=always -p 3001:3001 \
  -v /opt/uptime-kuma-data:/app/data \
  --name uptime-kuma louislam/uptime-kuma:2
```

   注意：不要用 NFS 挂载 `/app/data` [2]；先挂卷再建管理员账号，否则数据目录为空需重来 [3]。
3. 浏览器访问 `http://服务器IP:3001`，立即创建管理员账号（未建账号前任何访问者都可抢占实例 [3]）。
4. 逐个添加 20 个 HTTP(s) 监控：填 URL、间隔 60 秒、超时 30 秒、重试 2 次，接受 2xx 状态码 [1][3]。
5. 进入 Settings → Notifications 添加 SMTP 邮件（及可选 Telegram/Webhook），设为默认或绑定到各监控项 [3][2]。
6. 如需外网访问面板，配置反向代理与 HTTPS 证书（Let's Encrypt 免费 [5]）；仅内网使用可限制监听 `127.0.0.1:3001` [2]。
7. 验证：手动停一个测试站点，确认告警到达；观察数日后检查历史曲线是否持续累积。

## 五、一致性与缺口检查

- **步骤与依赖一致**：Docker 路径只需 Docker，不依赖 Node.js/PM2；端口 3001、持久化 `/app/data`、通知配置位置均有原文支持 [3][2]。
- **费用与步骤一致**：软件 0 元、证书 0 元、服务器既有；域名是唯一可能的新增现金项，按年价折算合计 ≤18 元/月，未超 300 元。
- **仍存在的缺口**：① 最小检查间隔具体数值未核实，方案用 60 秒规避；② 30 天历史无专门保留配置项，依赖持久化与持续运行，需实测；③ SMTP/Telegram 免费额度与速率限制未核实，无法确认 20 站点通知容量；④ 域名实价为页面挂牌价，随后缀与促销波动，以购买时为准。
- **假设**：服务器可装 Docker 且网络可达 20 个目标站点；5 人仅需查看告警与历史，不需多租户/SLA；预算按人民币计，电费带宽视为既有资源。
