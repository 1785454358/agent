## 一、主线与依据

Uptime Kuma 是开源自托管监控工具，按间隔检查 HTTP 等站点、记录响应时间、通过 90+ 通知提供方告警，数据存自有数据库 [1]。官方安装页给出 Docker 命令，镜像 `louislam/uptime-kuma:2`，映射 `/app/data`，端口 3001，并要求数据目录支持 POSIX 文件锁，避免 SQLite 损坏，支持主流 Linux 发行版 [2]。部署教程以 Ubuntu 24.04 为例，固定 `2.5.8` 镜像，端口仅绑 `127.0.0.1:3001`，数据放本地存储，勿用 NFS [3]。

HTTPS 监控：添加监控时选 HTTP(s)，填含 `https://` 的完整 URL，可设心跳间隔、重试、超时、接受状态码；默认 2xx 成功，默认跟随最多 10 次重定向并评估最终状态码 [4]。

通知：Settings → Notifications → Add New Notification 选 SMTP，填主机名、端口（465/587）、加密、用户名密码、发件地址；Gmail 需两步验证并生成 16 位应用密码，个人 Gmail 每日约 500 封上限 [5]。保存时有 Default Enabled 与 Apply on all existing monitors，可让通知覆盖全部监控项 [6]。

历史：监控、通知设置和运行历史全部存于 `/app/data`（SQLite），必须挂载持久卷，否则重部署丢失 [1]。按监控项自定义保留是未实现特性，已关闭为“不计划”；v2 只存聚合结果以提升性能，保留更多数据仍影响性能 [7]。全局清理任务的具体保留天数与可配置性在可见材料中未明确，属未核实。

## 二、检查频率与容量

心跳间隔默认 60 秒，可低至 20 秒；更短间隔发现更快，但增加被监控服务负载和数据库行数，60 秒对多数服务是合理默认 [4][8]。20 个站点 × 每 60 秒 = 每分钟 20 次请求，单机具体资源占用未量化，属未核实。建议重试 1–2 次、超时 15–30 秒，减少误报 [4]。

## 四、部署步骤

1. 确认 Ubuntu/Debian 等主流发行版，安装 Docker Engine 与 Compose v2，验证 `docker --version`、`docker compose version` [3][2]。
2. 建目录：`sudo install -d /opt/uptime-kuma && cd /opt/uptime-kuma && mkdir -p data backups`，数据放本地存储，勿用 NFS [3][2]。
3. 写 `compose.yaml`，固定镜像 `louislam/uptime-kuma:2.5.8`，端口仅绑 `127.0.0.1:3001`，挂载 `./data:/app/data` [3]。
4. `docker compose pull && docker compose up -d`，查 `docker compose ps` 与日志，确认无数据库/文件锁报错 [3]。
5. 浏览器开 `http://127.0.0.1:3001`，立即创建管理员账号（未建账号前任何人可抢占）[1]。
6. 配置 SMTP 通知，点 Test 验证收信，勾选 Apply on all existing monitors [6][5]。
7. 逐个添加 20 个 HTTP(s) 监控，填 https URL，间隔 60 秒，重试 1–2，超时 15–30 秒 [4]。
8. 验证：手动停一个站点看是否收邮件；确认 `/app/data` 有数据、重启容器后历史仍在 [1]。
9. 部署后进设置页核实全局历史保留期是否满足 30 天；若不满足，记录为未决项，不假设付费功能免费。

## 五、缺口与一致性核对

- **30 天历史**：可见材料只说明按监控项保留未实现、全局清理存在 [7]，未给出“保留 30 天”的显式配置项或默认值，属未核实；部署后应查设置页确认。
- **容量**：20 站点单机具体资源占用未量化，属未核实；60 秒间隔方向可控 [4]。
- **费用一致性**：步骤仅依赖 Docker、本地存储、SMTP 凭据；服务器与软件按 0 元增量，SMTP 若已有账户为 0 元，域名/证书为可选未核实项，故不能承诺总额以对应预算表为准。
