# 按证据变化推进研究：实现与验证

本轮覆盖三种研究策略的共用核验入口，不改变它们的路由、依赖顺序和分工。[完整规范及外部项目调研](../../superpowers/specs/2026-11-19-incremental-research-flow-design.md)含流程图、源码提交号、借鉴边界和验收标准。

## 根因与改变

原快照将预算、任务记录和全局运行状态绑定到同一个键。即便原文没有改变，运行状态变化也会导致再次核验；再次核验会重置全部覆盖，迫使模型重新判断已确认的需求。

现在由 `evaluation_delta.py` 统一协调，原有核验器只负责所分配的需求范围：

1. 原始任务、模型/规则、来源权限构成作用域；实际来源正文、版本、阅读范围及已接受结论构成材料依赖。
2. 相同材料和依赖直接复用结果。不同查询读到同一范围或子范围不算新证据；显式补读窗口另行处理。
3. 有新材料且存在已核验需求时，只为未完成需求组织原文与必要旧支撑，并传入精简的旧需求/结论目录。
4. 模型必须明确列出仍不受影响的旧需求；宿主验证编号、原文依赖、引用和合并后的覆盖。新结论的局部编号发生碰撞时重命名并重连覆盖。
5. 潜在冲突、影响判断遗漏、来源撤销/正文变化、规则或任务作用域变化触发重验。新增证据核验失败时，不拿上轮覆盖证明本轮完成，也不立即重试一个更大的整包请求。
6. 合并后重新计算进展，状态与真实证据对应；普通回答与带交付方案的回答均可使用局部修改协议，保留必要一致性和预算检查。

来源集合缩小时，原文窗口、材料指纹和合并验证均过滤范围外来源。当前宿主已经失效的结论不能从历史快照复活。未知影响不靠关键词相似度或模型自信跳过。

事件 `research.evaluation_scope` 记录 `full`、`delta` 或 `reused`，以及评估/保留的需求编号。其作用是解释执行过程，不是新的事实证据。

## 外部项目借鉴

- Open Deep Research：分支研究记录和主管材料分离，研究充分后结束并生成报告。
- STORM：信息表与章节检索分离，每个章节读取所需资料。
- DeerFlow：隔离子任务上下文，结构化结果与工具回执保持可追溯。
- Anthropic Research：研究期决策、引用处理和离线评估分别承担不同职责。

依赖失效与需求级合并是本项目的设计。没有把上述项目描述为共同采用同一套严格增量核验，也没有复跑它们来推断性能优劣。

## 同题真实模型冻结测试

原文与上一轮完全相同：两份已保存的 RFC 9110 / RFC 6585 正文。三种模式使用相同实际模型配置；所有 usage 均完整。计时包括研究、写作及复核，不含脚本冷启动。

| 模式 | 上轮调用 / 输入 token | 本轮调用 / 输入 token | 本轮输出 token | 本轮秒数 | 状态 |
|---|---:|---:|---:|---:|---|
| Workflow | 5 / 24,393 | 7 / 34,521 | 8,266 | 42.586 | partial |
| Plan-and-Execute | 7 / 43,840 | 6 / 29,343 | 8,971 | 43.812 | partial |
| Multi-Agent | 5 / 26,459 | 4 / 18,380 | 5,428 | 27.379 | partial |

关键事件证明流程实际生效：

- Plan-and-Execute：第一次核验 r1/r2/r3/r4；补查只核验 r1/r2/r4，明确保留 r3；后续没有新证据，复用覆盖。
- Multi-Agent：初次核验后没有新证据，下一步复用，没有再次发送全量核验。
- Workflow：增量影响判断未能确认，回退全量；该样本因此增加调用和输入。这是必要回退的实际成本，不能忽略。

这些是单次前后样本，生成的计划与需求分组不同，不代表稳定收益或受控统计消融。`partial` 仍表示证据或交付缺口，不能因为成本下降改名为完成。重复运行、中位数和最终答案人工质量验收仍需独立完成。

## 验证范围

回归包括：三种策略的增量合并；检查点恢复；轮次/预算变化；重复范围阅读；冲突与遗漏影响判断；模型预算失败；来源范围缩小；宿主失效结论；结论编号碰撞；方案终审局部修改及原有一致性检查。既有离线后端套件为 1,857 项通过、1 项真实联网测试排除，33 条依赖警告；收尾全量复测同为 1,857 项通过，77.24 秒；`git diff --check` 通过。
