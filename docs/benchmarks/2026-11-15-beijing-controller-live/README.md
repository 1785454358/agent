Agent 给出的主线为：第一天天安门广场—故宫—景山/什刹海，第二天颐和园—圆明园或周边，第三天天坛—前门/大栅栏—返程。住宿假设为两人合住分摊，日期未定时自行采用旺季口径。上述是被测 Agent 的建议，不表示本报告已独立核验旅行安排。

## 已确认的问题

1. **规划发生降级。** `initial_query_targets_degraded` 与 `initial_research_brief_degraded` 均出现，初始取材实际只搜索完整长问题。随后补查才转为两个定向查询，目标集中于故宫及天安门/国博/天坛/颐和园；住宿、餐饮没有获得定向补查。见 [diagnostics.json](diagnostics.json)。
2. **来源准入扩大了用户限制。** 研究简报为 null，问题没有“仅限官方”要求；但评估将旅游资讯、攻略与个人博客以非官方为由整体判为 ineligible，住宿和餐饮需求最终均以缺合格官方原文标 missing。票价与预约需要高可靠来源是合理倾向，但不能据此把所有预算参考也统一升级为“必须官方”。不同信息应采用不同的来源与不确定性规则。
3. **复合需求被局部标为 covered。** r1 同时要求故宫票价及预约；coverage 的 reason 仍说票价缺失，却给出 covered。r3 同时要求天坛、颐和园的票价和预约；reason 明示天坛缺失，却同样标 covered。引用合法、版本准确并不能证明需求的每个子项已经回答。整轮 partial 正确，不代表每项覆盖判断正确。
4. **已抓正文与评估结论不一致。** 故宫票务页面的持久化全文实际包含 60/40 元票价；但 accepted `finding-5` 仍称本次合格官方原文未核实故宫票价。最终 Writer 又给出了与抓取全文相符的 60/40 元，形成取材、评估和成稿之间的内部判断冲突。这不能直接归因于票价不存在；需检查阅读窗口、引用选段和否定性 Claim 的验证。相关位置与片段见 [body-audit.json](body-audit.json)。
5. **来源身份不等于时效保证。** 同一官方抓取全文仍包含核酸证明条款，说明正文混有需要核查适用时间的内容。本次最终回答没有复述该条款；不能因域名官方就将页面中的所有规则视为当前有效。
6. **交付可用性不足。** 有逐日行程和明确住宿分摊，但大量篇幅用于说明缺口，预算使用高额机动占位。国博、长城并非用户必选，却进入封存需求并成为未完成项，可能抬高不必要的验收负担；这需要结合原始问题复查需求拆解，而不是通过降低验证门槛获得 completed。

## 下一步修复顺序

先修 Planner 输出契约与降级后的查询拆分；再限制来源政策只能来自用户约束和宿主规则，允许带时间与不确定性标记的价格参考；随后修复复合需求的全子项覆盖和“未找到”类 Claim 的判定；最后检查 Writer 对未核预算与交付完整性的审查。
