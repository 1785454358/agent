结论：删除陈旧历史与保留合法工具调用结构并不冲突——文档的做法是允许用 RemoveMessage 删除或裁剪消息，但明确要求删除后的消息历史必须仍然满足 LLM 提供商的结构约束，尤其是工具调用配对与消息顺序 [1]。

具体调和方式：

- 删除是允许的：可以用 RemoveMessage 从图状态中删除指定消息，或用 REMOVE_ALL_MESSAGES 清空全部历史；前提是状态键使用 add_messages（Python）或 messagesStateReducer（JS）reducer，默认 AgentState 已提供 [1]。
- 删除有硬性条件：文档以 Warning 形式要求，删除消息时必须确保结果历史仍然有效，需核对所用 LLM 提供商的限制，例如：
  - 某些提供商要求历史以 user 消息开头；
  - 大多数提供商要求带工具调用的 assistant 消息后面必须跟随对应的 tool 结果消息 [1]。
- 裁剪是更安全的替代：可以用 @before_model 中间件（Python）或 createMiddleware 的 beforeModel 钩子（JS）裁剪历史，例如保留首条消息加最近几条，以控制上下文大小 [1]。

取舍与适用条件：

- 若删除会切断一对工具调用（删掉 assistant 的工具调用却留下 tool 结果，或反之），则该删除不合法；应整对删除或整对保留。文档只给出配对约束本身，未提供自动配对校验工具，因此配对完整性需调用方自行保证 [1]。
- 文档示例的裁剪逻辑按消息条数（保留首条 + 最近 3~4 条）实现，并未演示按工具调用边界对齐；在含工具调用的历史中直接套用该示例可能破坏配对，需自行调整裁剪边界（此为基于约束的推断，非原文事实）。
- 若无法确定安全边界，REMOVE_ALL_MESSAGES 全量清空是文档列出的合法选项，但会丢失全部上下文 [1]。
