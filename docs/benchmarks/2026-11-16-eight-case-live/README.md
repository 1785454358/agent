# 8题真实对照：质量有所改善，平均成本没有下降

本轮已完成 **8题、两组共16次真实模型运行**。模型为 `kimi-k3`，两组使用同一模型、冻结资料与预算。严格参考验收通过数从 **2/8提升至5/8**，但单题平均输入Token从 **16105.75增加至18103.125**。不能据此声称系统已全面达标、降低平均Token或降低幻觉率。

主指标与逐题复核见 `metrics.json`、`assessments.json`；每题原始回答、事件、来源及用量分别在 baseline / optimized 目录。`summary.json` 是实验采集程序生成的原始运行汇总，语义指标为空；`metrics.json` 才是本次完成复核后的汇总。原采集 `status.json` 的 awaiting_semantic_review 状态保留作过程记录。

## 实验条件

- 基线：当前 legacy Workflow，关闭末端事实审查。
- 优化：当前 controller Workflow，开启末端事实审查。
- 两组都保留共享安全、证据及预算治理；这是两种配置的组合对照，不是历史代码前后对照，也不是单机制消融。
- 每组8题，每题一次。按题交替A/B执行顺序；隔离运行身份、数据库及记忆。
- 每题相同14份冻结技术文档；资料哈希验证通过。参考答案、验收清单没有传给研究系统。
- 每次上限：20次模型调用、100000输入Token、600秒研究时间，来源目标3页。所有16次的供应商用量完整，没有用预算估计冒充实际用量。
- 8题覆盖六类任务，但均属技术文档领域，并且是历史开发用过的样本。不能称未见测试集、跨业务领域测评或显著性结论。
- 实验源代码哈希与运行结束后代码一致。正式任务启动信息见 protocol.json；本报告于客户端日期2026-11-16整理，保留原始UTC时间戳。

## 质量指标

| 指标 | 基线 | 优化 | 变化 |
|---|---:|---:|---:|
| 严格参考验收通过 | 2/8，25% | 5/8，62.5% | +37.5个百分点 |
| 预置验收项通过 | 13/25，52% | 21/25，84% | +32个百分点 |
| 运行状态completed | 5/8 | 6/8 | 不等于答案验收通过 |
| 运行状态partial | 3/8 | 2/8 | 保留全部记录 |
| 运行状态failed | 0/8 | 0/8 | 不代表所有问题答对 |

严格参考验收定义：回答有实质内容，并且该题全部预置参考验收项均被正确回答。允许运行状态为partial但最终答案满足这些验收项；不把completed直接当正确。

评分使用同一Kimi模型对匿名A/B回答进行逐项评审，组名及运行状态不提供给评分模型，再由本助手复核。它不是独立人工双人标注。需要说明：题1的参考清单额外要求字典例外，题4额外要求消息协议有效性，这些是较严格的参考边界，不等价于裸问题下的一般用户满意度。

### 逐题结果

| 题目 | 基线验收项 | 优化验收项 | 基线通过 | 优化通过 |
|---|---:|---:|:---:|:---:|
| 结构化输出字段与自动策略选择 | 2/3 | 2/3 | 否 | 否 |
| 新线程召回持久偏好 | 0/3 | 3/3 | 否 | 是 |
| HITL与原生结构化输出组合 | 3/3 | 3/3 | 是 | 是 |
| 消息裁剪、删除与摘要比较 | 3/4 | 3/4 | 否 | 否 |
| strict版本及供应商边界 | 1/3 | 3/3 | 否 | 是 |
| 自动选择与JSON Schema字典例外 | 3/3 | 3/3 | 是 | 是 |
| 删除历史与工具消息配对有效性 | 0/3 | 3/3 | 否 | 是 |
| 从文档判断通用最低费用/延迟 | 1/3 | 1/3 | 否 | 否 |

最后一题的两份输出都是通用“未能生成完整内容”兜底，没有明确解释为什么不能从文档推出排名。原模型评分把“没有说出排名”误作回答了不可推断性，复核将两组R1从covered改为missing，保留调整理由。R3是“不编造节省数字”的负向约束，保持covered；这不意味着问题得到回答。

## 成本与耗时

以下均包含未通过任务及系统末端审查开销，不筛选最好结果。

| 每题平均指标 | 基线 | 优化 | 变化 |
|---|---:|---:|---:|
| 模型调用 | 5.75次 | 6.50次 | +13.0% |
| 工具调用 | 2.875次 | 5.00次 | +73.9% |
| 输入Token | 16105.75 | 18103.125 | +12.4% |
| 输入+输出Token | 18008.625 | 20539.5 | +14.1% |
| 耗时 | 36.63秒 | 45.06秒 | +23.0% |

基线有两题没有取得可用来源并返回空洞兜底，成本更低不代表效率更好；优化版完成了更多取证，同时也增加审查和补查开销。因此本轮呈现的是质量与成本的取舍。

### 一个明确改善的多跳用例

`multi_hop-test-03`（HITL与原生结构化输出组合）两组均通过参考验收：

- 模型调用：15次 → 8次，减少46.7%。
- 输入Token：52108 → 19902，减少61.8%。
- 这是一个具体用例的观察，不能改写成“所有任务平均降低61.8%”。

### 探索性派生指标

将整组输入Token（包含未通过任务）除以参考验收通过的结果数：

- 基线：128846 ÷ 2 = 64423 输入Token/通过结果。
- 优化：144825 ÷ 5 = 28965 输入Token/通过结果。
- 分摊值降低55.0%，反映更多结果通过验收。这是看到结果后补充的探索性统计，受2与5这个小分母影响很大，不能称单任务平均Token下降或稳定的业务成本收益，不建议作为首要简历指标。

### 额外评测开销

语义评分单独发生16次供应商调用，包含格式失败及修复；输入86838、输出45974 Token。该开销不计入被测系统单题成本，完整记录在 judging 与 judging-retry-v2 的 usage.json 中。服务预检另行记录，不算正式任务消耗；未给出货币金额，因为没有采用经过核实的单价及账单信息。

## 为什么没有发布“幻觉下降X%”和“引用支持率提升”

保留了逐条事实与引用的原始匿名评分，但复核发现评分器可靠性不足：

1. 版本题中，评分模型将供应商边界验收项判为incorrect，却把相关事实片段判为supported，内部不一致。
2. 抽取片段中存在复合断言和重复语义，不能稳定当作原子事实分母。
3. 某些明确标注的合理推导被引用评分机械标成partial。

原始模型引用关系计数为基线42/42、优化53/57，但**不采纳为可靠引用支持率**，也不能用原始事实评分推导“幻觉为0”。正式汇总中的无依据事实率和引用支持率保持null，后续需要更稳定的断言拆分及独立标注复核。

冻结语料没有实际网页搜索，本轮也不能提供联网重复检索率。既有4项受控故障回归可见前一轮报告，不能从本轮问答通过率推算恢复率。

## 仍暴露的问题

- 两组都漏掉了部分参考边界：字典例外、消息协议有效性。
- 优化版“删除历史”用例回答满足参考要求，但运行状态仍为incomplete_plan，说明执行状态与最终交付需要分别评估。
- 证据不足用例有可用文档，却因没有正向事实finding最终变成通用空答，而没有明确交付“无法推断以及缺少哪些数据”。
- 加入更多补查和审查尚未带来总体平均降本，后续优化需要对上述具体失败路径进行改进，再用新样本复验。

## 可用于简历的表述

推荐优先写质量实验，保留小样本范围：

> 构建包含六类任务的8题冻结文档开发集，完成两组共16次端到端对照；结合匿名模型评分与逐项复核，将严格参考验收通过率由25%提升至62.5%，验收项通过率由52%提升至84%，并定位版本边界混淆、漏答及证据不足时的空答问题。

如需体现具体效率案例，可单独写：

> 在一项多跳文档回归用例中，统一控制器配置将模型调用由15次降至8次、输入Token由52.1k降至19.9k；通过运行级预算和末端资源预留约束长链路执行成本。

两种配置同时改变编排与末端审查，不能将以上效果全部归因某一个模块；当前也不适合写“整体Token下降”“幻觉率下降”或“所有任务均完成”。
