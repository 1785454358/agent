# 复杂任务部分完成：诊断与修复

2026-11-18，以此前两个原始问题复盘检查点、搜索/抓取结果、实际阅读范围和模型预算，再进行真实网络复测。

## 已定位的环节

1. **发现阶段丢失文档版本。** 版本识别包含“依据”，但不包含原题使用的“根据”。检索反复发现 Python 最新版，3.11 的关键页面未进入读取；严格版本校验随后正确拒绝了最新版。现已支持“根据／按照”，并允许通过真实 API 索引链接继续定位参考页。链接发现和抓取继续经过工具授权、公共 URL 检查及原预算；冻结资料集不外扩。
2. **材料窗口偏向早期来源。** 核验和补读导航只考虑前 8 个来源。跨语言任务虽然抓到了 16 页，后续来源仍可能被隐藏。现允许最多 32 个来源参与全局预算下的阅读组选择，并同步修改来源编号、评估输出协议和来源检查容量；保留来源隔离、真实原文引用校验及省略诊断。
3. **复杂策略只搜索、不补读。** Plan-and-Execute 与 Multi-Agent 原来没有启用已有的定向补读能力。现共享补读执行：先读实际段落，再评估，尚有缺口才派发备用搜索。备用搜索重新按最新缺口过滤；补读与其备用搜索共享同一轮次，最后一轮也能执行；检查点恢复不会重复搜索。
4. **规划异常破坏分工或范围。** 可选说明校验失败可能将三条分支压成整题查询；模型也曾把六个需求名额全部分给前两种语言，却让第三种语言引用不存在的 r7–r9。现对结构不一致的完整规划执行最多一次受预算约束的修复；修复后的明确需求映射和分支说明共同确定实际查询。仍失败时保留完整原问题作为验收范围，不把缺失对象排除在外。只有映射有效而可选元数据损坏时才直接保留已解析查询。
5. **重复评估耗费预算。** 来源被拒绝后，原先两个策略可能再次请求模型对同一材料给出第二意见。现与已有控制器策略一致：宿主保持拒绝结果，把恢复用在新原文；JSON/协议错误仍有一次修复机会。
6. **后续核验失败丢失已验收内容。** 两个独立策略原来会在预算/传输失败后重置已有发现。现复用控制器的保留逻辑，重新检查来源生命周期、版本和正文哈希后保留已验收结论；已变更或撤回的来源不保留，旧覆盖状态不会被复用为新窗口的完成结论。同时，循环核验按剩余输入预算的三份之一选择材料，为后续恢复与成文留出空间，最终仍由共享预算网关执行原子准入。

## 验证口径

- 本地 API、全新对话、请求模式 `auto`；实际独立策略执行。
- 模型 `qwen3.8-max-0902`，20 次模型调用、100000 输入 token、600 秒研究预算，均未上调。
- 使用 lexical 记忆配置，与原基线一致；这两个任务的故障位于规划和证据流程。
- 网络搜索与模型输出存在波动，单次完成不代表正确率保证。覆盖状态、最终回答的事实质量和可执行代码实测分别判断。
- 中间一轮发生模型连接断开，该轮不作为修复有效性的证据；后续复测重新建立新对话。

实测数据与剩余限制见 `measurements.json`。测试覆盖多来源完整评估协议、冻结资料边界、规划错误范围保全、三分支恢复、补读后取消备用搜索、最后一轮恢复及断点续跑。
