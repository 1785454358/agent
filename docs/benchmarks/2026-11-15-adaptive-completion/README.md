# 自适应完成闭环：实施与验证

本轮没有获得新的真实回答质量通过结论。北京旅行与网站监控两项真实运行，在首次 planner 请求时都收到模型供应商 HTTP 429：`credit_quota_exceeded / Token Plan Person monthly quota limit exceeded`。

## 已实施

- 复用补查调用，返回可选的交付方案修订、原因和已验收结论编号。宿主保留全部需求，校验引用，保存旧方案；修订后事实覆盖重新核验，下一分支及最终 Writer 使用新方案。
- controller 最多三轮，首次补查无进展仍可选择另一条新查询；重复已派发查询被拒绝。补读仍最多一次，原有调用、输入 Token、时限及收尾预留继续生效。
- 从已授权且 active 的原文提取真实链接，最多选两个相关链接加入后续分支候选；继续经过正常来源选择、URL 安全检查、抓取、阅读。冻结语料不向外导航，链接文本不充当事实。
- 预算行区分 selected / optional。未选择的附加项目展示但不计入主线合计，不将其未知价格当作主线缺口；必须说明排除理由。主线未知费用仍保留缺口。
- 默认入口切换 controller；三种公开模式保持兼容，显式 legacy 可回退。真实 `.env` 未修改。
- 区分普通限流与额度耗尽；后者不进行传输重试，并在本次运行预算快照中保存阻碍，拒绝后续角色的模型派发。新运行可重新尝试。回复明确说明额度与恢复条件。

## 验证边界

回归覆盖真实执行分支的第三轮成功、方案修订进入下一分支并传到最终结果、需求及硬约束保留、非法修订拒绝、重复查询停止、搜索空结果时沿真实链接取证、冻结语料与内网地址保护、可选费用不污染合计、额度错误不重试且跨恢复生效。

在 backend 目录执行完整非联网测试：`.venv/Scripts/python.exe -m pytest -q -m "not real"`。最终结果为 **1671 passed, 1 deselected, 33 warnings，59.85 秒**，包含方案修订贯穿执行的端到端测试与最后补充的额度错误归类断言。

首次未加 marker 的全套运行也触发了一个已有的真实 smoke 测试，因同样的额度错误失败；另有两项旧调度次数断言因新恢复策略失败，随后调整为检查不重复抓取/评估，已纳入最终通过的非联网测试。

## 仍需实测的部分

第三轮与来源导航使系统有更多有效行动，不能证明模型一定会选对行动。方案语义、可选项是否确实可省略、估算是否合理，仍需要模型结合原文判断；宿主校验结构、身份、覆盖重新核验和算术，不能证明世界事实。恢复模型服务额度后，应使用相同问题和原有20次/100000输入Token/600秒上限完成新一轮真实验收，再评价回答质量。
