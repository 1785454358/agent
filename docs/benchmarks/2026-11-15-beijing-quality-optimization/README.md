## 已修复并验证的内容

1. 缩短 Planner 通用提示；controller 的可选规划元数据失败时，保留独立合法的查询。增加独立交付维度的查询分配提示。
2. 默认发现任务最多读取 3 页，与原有来源目标一致；全局预算不变。
3. 分支模型调用恰好达到局部上限后，允许继续执行已选来源的抓取和阅读；额外模型调用仍被拒绝，全局预算仍约束采集。
4. 来源限制声明需要真实用户原文依据，不能把规划自加的“仅官方”当授权；显式复合缺项不能标 covered。
5. 原文补读导航按缺口相关性选择最多 24 条，删除重复标题和网址。优化 1 的 Replanner 消耗 25,517 输入 token，末轮为 8,675；不得将这个局部改善说成总 token 降低。
6. 评估与写作选择材料时参考剩余输入额度，区分模型输出预留和运行输入上限，修复重复扣减。实际准入继续由持久化预算网关负责。
7. 已由宿主删除、且不参与 covered 判断的不合格发现，不再触发整批重复评估；影响覆盖的拒绝及未经授权的来源限制仍可修复。末轮 Evaluator 为 3 次，而优化 3 为 5 次。
8. 最终审查遇模型额度或供应商调用失败时，保留后续引用校验通过的草稿，显式标注未经最终事实审查并保持 partial；非法审查结果仍被拒绝。
9. Writer 的运行输入额度比模型窗口更紧时，优先已验证引用和原有邻近段落、边界上下文，停止附加额外页面选段，避免早期来源的附加内容挤出后续有效证据。未受运行窗口约束的路径保持原有选段；验证引用不按字符盲截。

## 第四轮答案人工检查

有进展：每日顺序、住宿分摊假设、预算区间和预约列表都能输出；故宫票价实际进入答案；八达岭材料注明来自 2019 年，未冒充已核实的当前规则；未再用机动项直接凑满 2000 元。最终审查成功执行，未发生模型预算准入失败。

仍未达标：

- 住宿只有“地铁沿线经济型酒店”这一泛化建议，缺具体区域及有日期条件的价格依据；餐饮仍缺可靠人均参考。抓取到资料不等于已经获得所需信息。
- Planner 仍把用户未指定的多个景点及机场接驳扩为必要事实。提示约束没有稳定解决过度展开，五项复合需求均为 missing；该结果不能被当作质量通过。
- 已接受的 `finding-4` 包含天坛旺淡季票价，Writer 因窗口选择丢弃整项来源，最终却仍写天坛票价未核实。这个缺口属于材料传递损失，不能归因于单一搜索提供商。可对照 [body-audit.json](attempt-4/body-audit.json)、[diagnostics.json](attempt-4/diagnostics.json) 与 [result.json](attempt-4/result.json)。
- 预算表本身下限 1110、上限 1610 加总正确；但单人房差额写成 300—450，按表中房价应为 300—400。总额上限 2010 已超过 2000，首段仍称“预算仍可成立”，需要进一步一致性检查。最终模型审查没有纠正这些错误。
- 末轮没有预算超限，但 84,872 输入 token 的成本仍偏高。评估材料选择、来源新鲜度及建议与事实的分界仍需继续优化。

下一步应优先解决“已验证证据在 Writer 窗口丢失”和“未选候选被封存为必查项”，再改善酒店/餐饮发现与数值一致性；不要靠换更大额度或把 partial 改为 completed 掩盖这些问题。

## 第五轮最终检查

原始答案见 [attempt-5/answer.md](attempt-5/answer.md)，运行 `beijing-live-b156e63999ea`。11 条收集证据、10 条接受发现，最终引用 7 个 URL；模型 12 次尝试均有 usage，输入 85,725、输出 9,890 token。Evaluator 38,632 输入 token，Writer/审查 21,873。工具执行 40 次，2 次失败。没有模型预算准入失败；没有 `response.budget` 材料丢弃事件。最终审查成功完成。

回答已能交付每日路线、住宿区域及单双人分摊、预算区间、预约事项与集中限制说明。单人预算下限 `600+126+40+450+100=1316`、上限 `900+146+40+600+200=1886`；两人分摊对照为 1066—1486，均能由表中项目加总。故宫票价、国博预约、地铁定期票资料与住宿区域建议进入回答，攻略价格与已核价格作了区分。未再复现第四轮那种整项来源因额外选段被丢弃的问题；这只是单次观察，不能证明所有输入下均不会丢失材料。

事实完整性仍未通过：酒店和餐饮没有对应日期下的市场费用依据，部分景点价格及提前预约天数依赖攻略。地铁三日票不能直接覆盖八达岭往返所需的全部交通，回答将市内交通统列 40 元不够完整。Planner 仍枚举多个用户未指定的候选，并封存机场接驳等额外范围；系统覆盖为 1/5，其本身也是模型判断，不是人工准确率。此案可以作为明确假设的旅行规划草案，不能作为已完整核实的成品方案。

后续主要方向是减少未选候选成为强制需求、改善商业价格发现，以及核查路线、交通方式与预算之间的一致性。第五轮的窗口修复已有失败回归，但仍需多题与重复真实样本验收。
