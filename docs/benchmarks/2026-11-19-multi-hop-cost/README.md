## 用量与交付核对

- 改造前评估角色三题共使用 48,245 输入 Token。当前运行没有该角色调用，规划、取材和写作的用量也发生变化。这里比较的是整个架构前后版本。
- 总工具调用从 149 降到 111，降幅集中在线程记忆题。另两题的工具调用上升。本轮统计总调用数，重复查询次数需要从工具入参或账本另行核算。
- 旧版三个目标均返回带引用的有限答案，其中两次记录 `response_error`，一次记录 `planning_limit`。新版三个目标均返回带引用的正文，来源范围和模型预算检查前后均通过。
- 按题目参考要点检查了原始正文。新版覆盖审批恢复与幂等、持久化与工具身份注入、审批及结构化输出的各项核心问题。线程记忆题有一处术语问题，把业务待办与框架的 pending writes 混用。两版均保留原始回答，本轮使用人工要点检查，未做独立盲评。

## 条件与复现

- 基线取自 `.local-artifacts/delivery-first-baseline-20261119`，核对了其中 207 份 Python 文件与快照清单。候选为当前工作区。两版 lock 文件一致，实际运行也使用同一套虚拟环境。逐次结果保留源码指纹。
- 两版均使用 `deepseek-v4.1-flash`，关闭研究侧 thinking，设置 20 次模型调用、100,000 输入 Token、每次最多 16,000 输出 Token，并开启同一配置项下的事实复核。两版按顺序各执行同一组题，各题隔离线程，使用临时 SQLite，关闭跨题记忆。
- 冻结语料为 14 份官方 LangGraph/LangChain 文档，正文 SHA-256 逐份验证。两版通过实际工具选材和阅读；网络搜索与抓取由冻结材料替代。参考要点仅用于事后检查。
- 每题每版一次。实验用于描述本组三题的实测成本和交付差异。完整题目、设置、原始回答、来源和角色级用量见 [results.json](results.json)。本地执行命令如下，从 `backend` 启动。
