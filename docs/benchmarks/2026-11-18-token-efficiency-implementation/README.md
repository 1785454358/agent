## 已实现

| 问题 | 实现 | 边界 |
|---|---|---|
| 规划字段重复、映射键不一致 | 只要求模型生成需求和 `tasks(id, query, requirement_ids, read_terms)`；宿主派生旧查询映射、任务简报和读取词 | 旧响应/检查点仍能解码；非法任务整体回退原问题；约束超出数量限制时合并保存，不截断 |
| 明确来源仍逐分支调用模型 | 唯一用户指定 URL、唯一匹配的 RFC 文档标识由本地选择 | 多个镜像/版本有歧义时仍调用模型；选择不代表原文已获事实资格 |
| 核验后再次调用长补查规划 | 三种实时核验结构均可携带最多两条 `recovery_tasks` | 宿主按当前缺口、真实需求编号和已派发查询重新过滤；历史响应省略时保留原恢复路径 |
| 重复核验同一输入 | 持久化本次运行的核验快照，绑定任务、租户、来源正文/版本/状态、阅读范围、模型参数和规则源码摘要 | 不接入长期记忆；输入、模型、约束或规则变化即失效；失败核验不缓存为通过 |
| 旧材料反复占窗口 | 增量材料窗口省略已核验、且不承载保留结论的完整旧阅读组 | 保留结论所在阅读组、新材料、显式补读及可能冲突的原文；覆盖仍逐项重判，不能确认影响范围时全量核验 |
| 修复结构时引用窗口改变 | 同一次核验的结构修复复用确切原文窗口和引用编号 | 不能借结构修复切换资料；最终消息按实际序列化封装计量，避免小幅超预算 |
| 大文档无法取得 | TXT 原文受限读取、PDF 显式页段提取、整份受限正文上的本地结构检索；保留实际 HTML/TXT 下载链接 | 下载最多 8 MB、正文最多 100 万字符；PDF 每次最多 100 页，标注实际页码和未读页；URL、时间、存储限制仍有效 |
| 重定向循环 | HTTP 传输保留服务器 Location 的末尾 `/`，文档身份仍按原规则规范化 | 每跳继续验证公网 URL，仍有重定向次数上限 |
| 无效补查反复失败 | 跨分支传递本次运行已观察到的永久失败；同一 URL/版本/格式的瞬态抓取失败允许一次新尝试 | 新版本/格式的实际 URL 独立处理；不把不合格新来源算作研究进展 |
| 复核重复生成全文 | 普通任务返回精确、唯一且互不重叠的修改片段；无修改返回空数组；按任务加载科研/HTTP规则 | 旧全文协议可兼容；交付方案保留结构化一致性核对；保留来源、引用和代码约束检查，不执行生成代码 |
| 复核遗漏 POST 风险开关 | 对指定无去重前提的 POST 重试，拦截已复现的 `acceptDuplicateRisk` 绕过保护代码模式，并要求有界修订 | 这是已知错误模式的额外检查，不是对任意生成程序的形式化证明；两次仍失败不发布该答案为已核验结果 |
| 风险开关改名或网络调用突破总时限 | 检查正文中的业务风险许可策略，以及已复现的未绑定剩余预算的 `send` 调用 | 不执行未知代码；无法完成定向修订时返回受控部分结果，不能仅凭模型“无问题”判通过 |
| 看不到固定成本 | 每次调用记录规则、Schema、证据、任务/历史文本的本地 token 估算及安全的实际请求参数 | 估算不等于供应商账单；provider usage、缺失次数、失败调用独立保留 |

## 实测口径

原始在线基线来自同一道 HTTP 重试题；改造中的在线重跑记录位于 `.local-artifacts/http-retry-three-modes-20261118-efficient-v4/`。该轮 Workflow 为 **8 次、29,566 输入 token、88.31 秒、partial**；旧在线基线为 **10 次、46,851 输入 token、84.75 秒、partial**。输入下降不代表耗时一定缩短或质量已通过。

该轮 Plan-and-Execute 在写作阶段连续发生服务端断连，最终 failed；Multi-Agent 在搜索阶段失败，最终 partial。失败样本保留，不能用它们的较少调用数声明优化成功。另一次带真实模型的 smoke 测试遇到 `answer_review_unavailable`，也未记为通过。

为了排除搜索/抓取波动，另将原先实际取得的 RFC 9110、RFC 6585 两份原文冻结，三种模式共用相同正文 SHA-256，模型保持真实调用。冻结语料通过正式来源作用域传入，禁止搜索、抓取或导航扩大语料。

中间验收（v6；最终精简复核和 POST 额外拦截之前）：

| 模式 | 模型调用 | 输入 token | 输出 token | 秒 | 研究状态 |
|---|---:|---:|---:|---:|---|

| Plan-and-Execute | 6 | 36,038 | 10,449 | 70.674 | max_replans_reached |
| Multi-Agent | 5 | 27,006 | 8,020 | 52.260 | max_follow_ups_reached |

三次 usage 均完整；不含 Python 冷启动，计时覆盖本轮研究、起草和复核。它们与旧在线基线并非同语料的前后消融，不能把差值解释成纯改造收益。Plan-and-Execute 的输入仍略高于 25–35k 的目标上沿。

这两轮证明流程能完成到回答阶段，但没有证明证据完整性验收通过；冻结语料也不能代替真实全网取证的质量比较。

## 质量结论与限制

成本下降已经出现，**完整性验收尚未全部通过**。HTTP 的覆盖缺口主要涉及本次可见原文范围、503 完整定义、非幂等重试条件及自行建议与规范事实的边界。不能通过缩小原问题或把 partial 改成 completed 达标。

v6 人工检查还发现 Plan-and-Execute 伪代码允许业务风险开关绕过 POST 保护，故该样本不计关键质量项通过；它促成了之后的额外检查和回归测试。Retry-After 超过剩余预算的停止条件与该 POST 条件分别检查，不因一项通过而判整个代码通过。

当前核验复用采用保守策略：复用完全相同的已核验输入，或减少旧的无支撑阅读组；没有启用仅凭模型自信跳过覆盖判定的激进缓存。PDF 页段已提供受限工具入口；没有目录或明确页码时，不把任意前 100 页冒充整篇。

## 复现

从 `backend` 运行：

```powershell
.venv/Scripts/python -m pytest tests -m 'not real' -q
.venv/Scripts/python scripts/benchmark_frozen_efficiency.py --sources ../.local-artifacts/http-retry-frozen-sources.json --question ../.local-artifacts/http-retry-three-modes-20261118-efficient-v4/question.txt --output ../.local-artifacts/http-retry-frozen-new-run
```

输出目录必须是新目录。脚本会保存逐模式回答、实际 usage、事件和冻结来源摘要；`--modes plan_execute` 可选择单一策略。开发工具适配器提供受限语料，模型响应不模拟。局部估算与实际 usage 必须分开阅读。
