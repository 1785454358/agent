# 真实研究案例：北京 3 天 2 晚自由行规划

这是一次使用本地 DeepResearch 项目、真实模型、Tavily 搜索与网页抓取完成的旅行规划研究。运行日期：2026-11-12，策略：Workflow，状态：completed。

## 用户问题

> 第一次去北京，安排一个3天2晚的旅游行程，预算每人2000元（不含往返大交通），希望兼顾经典景点和当地美食，请说明行程、预算及需要提前预约的事项

## 研究过程

1. Planner 拆出经典景点、交通与住宿、预约要求、美食等研究方向。
2. 通过 Tavily 搜索候选来源，再逐页抓取正文；部分旅游站返回 `insufficient_content` 或 `browser_failed`，被明确记录为材料缺口。
3. 按需求读取原文证据，保留故宫、颐和园、天坛等官方页面。
4. 证据评估后，Writer 仅依据可用原文生成回答；缺少房价、餐饮人均等信息时标注“待核”，不编造数字。
5. 最终事实审查通过，状态 completed。

## 原始回答

以下保留本次运行的完整回答文本：

**结论：可行，但2000元/人（不含往返大交通）要按“住经济型、吃平价、少打车”来安排。** 3天2晚建议：D1天安门广场—故宫—景山/王府井；D2天坛—前门大栅栏—什刹海；D3颐和园—返程。故宫不售当日票，须提前实名预约[1][2]；颐和园、天坛淡季票价可查[3][4]，但二者是否需提前预约，现有材料未明确。餐饮、住宿、市内交通的具体价格在现有材料中缺失，预算只能给框架，不能给精确分项。

## 行程安排

| 日期 | 行程 | 说明 |
|---|---|---|
| D1 | 天安门广场→故宫→景山公园→王府井 | 故宫午门为唯一入口，须持预约证件原件检票[2]。天安门广场预约规则现有材料未明确；如已预约天安门广场与故宫两处，可按[2]经广场周边安检口前往，天安门城楼至故宫午门为南向北单向通行[2]。 |
| D2 | 天坛公园→前门大街/大栅栏→什刹海 | 天坛淡季联票28元、门票10元；祈年殿等景点8:00开门、16:30停止进入、17:00关门，逢周一关闭（法定节假日正常开放）[4]。前门、什刹海为建议串联，非原文固定路线。 |
| D3 | 颐和园→返程 | 颐和园淡季门票20元、联票50元；公园6:30—19:00（18:00停止入园），园中园8:30—17:00，园中园周一闭园[3]。 |

取舍理由：一天安排1—2个大景点更稳妥，北京景点面积大、步行多[5]；D1中轴线景点集中，D2天坛与前门、什刹海方向相近，D3颐和园单独留半天以上。

## 预算框架（每人）

| 项目 | 金额 | 依据与说明 |
|---|---|---|
| 门票 | 约100—150元 | 故宫淡季大门票40元，珍宝馆、钟表馆各10元[1]；颐和园联票50元[3]；天坛联票28元[4]。上述合计约138元；景山等未列票价，按少量余量计，未含未列景点票价。 |
| 住宿2晚 | 待核 | 现有材料只建议住二环内、地铁一号线/八号线沿线，天坛周边价格实惠，但未给具体房价[5]；另有“200—250元/晚可能住到四环或五环外”的参考[5]，非确定房价。 |
| 餐饮 | 待核 | 材料列出方砖厂69号炸酱面、全聚德、四季民福、南门涮肉等，但未给人均消费及订位要求[5]。 |
| 市内交通 | 待核 | 材料建议市区用地铁或公交、优先地铁，但未给票价[6][5]。 |

因此，2000元能否覆盖，取决于住宿与餐饮实际支出；门票部分较可控。建议订房前先核实房价，并把烤鸭等正餐控制在1—2顿。

## 必须提前预约/确认

1. **故宫**：不售当日票，门票及珍宝馆、钟表馆于参观前7日20:00开售，限参观当日有效；须通过官方“故宫博物院”小程序实名预约，未授权第三方代理；周一闭馆（法定节假日除外）；内地观众仅用身份证，同一证件每参观日仅能预约一张；分上午、下午时段，上午最迟12:00检票、下午最早11:00检票[1][2]。
2. **天安门广场**：现有材料未明确其预约规则、渠道和提前时间[2]，建议出行前向官方渠道核实。
3. **故宫内部分展览**：须预约，以预约页面信息为准[2]。
4. **颐和园、天坛**：票价与开放时间明确[3][4]，但现有材料未明确是否需提前预约及购票渠道，建议出发前核实。
5. **餐厅**：现有材料未说明所列餐馆是否需订位[5]，热门烤鸭店建议提前电话或平台确认。

## 运行中发现并修复的问题

首次运行在工具账本处失败：

```text
sqlite3.OperationalError: no such column: tool_executions.mode
```

根因：本地 SQLite 为旧 schema，`ensure_sqlite_schema` 迁移了 evidence/memory 表，但漏掉了 `tool_executions` 的 `mode`、`caller_id`、`consumed_tool_calls`、`consumed_network_requests`、`consumed_fetched_pages` 五列。

修复：

- `backend/src/deeptrace/persistence/schema.py`：在创建索引前补齐缺失列。
- `backend/tests/application/test_local_memory_persistence.py`：新增 `test_sqlite_schema_migrates_legacy_tool_ledger_columns`。

验证：`uv run --no-sync pytest tests/application/test_local_memory_persistence.py -q`，3 passed。
