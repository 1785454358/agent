# 设计参考与演进方向

调研日期：2026-10-04。以下内容参考项目官方仓库，侧重研究类 Agent 的产品表达与工程设计。各项目定位与评测条件不同，这里不作性能排名。

## 同类项目的展示方式

| 参考项目 | 官方材料中的重点 | DeepResearch 的展示取舍 |
| --- | --- | --- |
| [GPT Researcher](https://github.com/assafelovic/gpt-researcher) | 先介绍研究用途和报告产物，再说明规划、执行与来源汇总；提供演示、安装和文档入口 | 首页先让读者看到研究任务、工作台和带来源的回答，再解释内部实现 |
| [Open Deep Research](https://github.com/langchain-ai/open_deep_research) | 快速启动、模型与搜索配置、可查看的评测实验，以及部署和使用入口 | 将免 Key 体验、真实案例和可核对的评测记录放在清晰入口中 |
| [DeerFlow](https://github.com/bytedance/deer-flow) | 以完整任务工作台组织使用体验；提供不同启动方式、只读演示及独立架构文档 | 保持轻量演示，将产品介绍与架构细节分层组织 |

以上是展示与设计参考；功能实现以 DeepResearch 当前源码为准。

## 当前实现的组织重点

- 三种研究策略共享批量取材与集中整理管道，方便在相同运行规则下观察不同编排方式。
- 模型和工具具有统一 Gateway，预算、重试与执行记录集中在明确边界。
- 搜索、抓取、阅读、评估和写作之间传递证据标识与原文支持。
- 运行事件、答案和来源通过工作台展示，支持本地体验和真实运行记录复查。

这一定位适合展示 AI 应用开发中的编排、上下文组织、证据治理与运行可靠性经验。

## 演进方向

以下内容为后续规划：

| 方向 | 可参考的成熟实践 | 预期产物 |
| --- | --- | --- |
| 产品体验 | GPT Researcher 的报告交付与导出入口 | Markdown 阅读体验、引用跳转、报告导出 |
| 低门槛体验 | DeerFlow 的只读演示；Open Deep Research 的配置入口 | 可直接打开的静态演示、清晰的模型与搜索配置引导 |
| 评测呈现 | Open Deep Research 的实验身份与结果入口 | 多任务评测卡、配置登记、质量与资源消耗对照 |

这些参考用于明确演进顺序；不直接沿用其他项目的指标，也不将规划描述为当前能力。
