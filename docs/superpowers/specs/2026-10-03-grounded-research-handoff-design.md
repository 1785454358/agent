# 定向阅读与带来源研究发现：共享链路简化设计

## 目标与已确认边界

用户已确认：参考开源研究 Agent 的做法，重构共享取材与结果交付，而不是继续增加门禁或整体替换框架。目标是提高关键事实获取和完整回答能力；保留 Harness、三种模式、证据权限、checkpoint、失败恢复和真实不足时的 partial。P&E 为主指标，Workflow、Multi-Agent 同测；Answer 为主，Report 独立回归。

本文件是待书面审阅的规格，不表示已实现或质量已提高。此次只修改共享阅读、研究发现交接和相关规划/评估提示，不改记忆架构、模型、评分标准、gold 或调用上限。

## 实证依据与方案取舍

上一批记录见 [support-budget-validation-20261003.md](../../evaluation/support-budget-validation-20261003.md)。只读追踪实际工具消息和 evaluator 输入后确认：

## 数据流与唯一职责

原始问题与 requirements → 定向搜索/阅读 → record_findings 保存候选发现 → 共享 evaluator 判覆盖与缺口 → 定向补查或 Writer。

1. **Planner：** 复用已封存的 requirements 和 execution_constraints，不增加第二套 ResearchBrief 状态。过程问题明确操作、必要输入、适用条件与重执行风险；比较问题明确比较维度。只补足完整回答原问题所需的义务，不臆造用户偏好、不强制每题凑满六项。
2. **Reader：** 负责找到并展示原文；宿主负责给真正展示的引用单位编号。
3. **Researcher：** 负责提炼候选结论并及时记录，不能自行铸造原文坐标、证据权限或 covered。
4. **Evaluator：** 仍是唯一的全局覆盖判定入口，同时看候选结论与实际可见原文，判断相关性、蕴含、完整性及冲突。缺口沿用既有 research_gaps 和 target_requirement_ids。
5. **Writer：** 使用现有全局已验收 Finding 与 EvidenceSupport；不直接使用未经评估的分支笔记冒充已证明事实。

三模式只保留任务调度差别，不复制 Reader、记录、引用解析或覆盖逻辑。无向量库、知识图谱、reranker 服务、新 Critic Agent、独立笔记数据库或额外摘要模型。

## 定向阅读：增强原工具，不新增浏览工具组

保留 read_evidence 的 query/start 行为；增加可选 find 和 after：find 是 1–200 字符的原文精确子串，after 为严格非负字符偏移，默认 0，且只能随 find 使用。query、start、find 三种选择方式互斥。find 按 Python 原文字符坐标搜索首个命中；不做会改变坐标的文本规范化。返回命中附近的原文，沿用 1–3000 字符 limit；find 长于 limit 时拒绝参数。

selection 显式返回 found 与 next_start，后者为命中子串末尾。没有命中时返回空 passages、found=false，不悄悄改成页首片段；这仅代表该词未命中，不证明文档没有答案。重复定位由模型把 next_start 作为 after；范围读仍可查看相邻步骤。查询模式仍用于自然语言检索，find 用于已看到的标题、API 名或专有词。

共享提示要求先针对目标需求定向阅读、提取关键术语，再补查缺失内容；已抓取页面可能解决的缺口先重读，来源确实不足再搜索。不能连续同参数无进展读取，也不把扫描完整网页当作完成条件。页内定位不自带跨语言语义能力；词项从任务或实际来源生成，不注入已知 dev 的恢复调用、URL 或 gold。

## 及时记录：一个内部工具，一种事实载体

新增共享内部工具 record_findings，与 write_todos 一样只更新分支状态，不执行外部写入。一次提交 1–5 项，字段为 claim（1–1000 字符）、refs（1–3 个不同短编号）、confidence（0–1）。模型不提交 Finding ID、quote、坐标或 covered。一个发现可以包含有条件的操作步骤；缺乏原文支持时不记录为事实。

短编号使用分支内稳定的 n1、n2…，与 evaluator 每次调用重新生成的 p1、p2… 明确分开。宿主在成功 read_evidence 的实际最终工具预览中，把原文拆成不超过500字符的引用单位并显示编号；复用现有切分与原文校验函数。必须在完整 JSON 预览限额内重新排版、裁剪和校验，只注册实际展示的整块单位；不能先注册再把正文截掉。

引用登记表只保存短编号到来源/版本/hash/字符范围的映射，不存整篇正文。每分支最多128项，按工具调用索引确定性分配；相同来源和范围复用编号，已发编号永不重绑。超限时明确诊断，未登记单位不能用于记录。编号只属于当前分支，不能从别的分支、运行、租户或任意模型消息导入。旧的 read_anchors 继续作为有界读取轨迹，不作为另一份笔记或语义证明。

记录时宿主检查当前分支授权、来源 ACTIVE、版本/hash、已展示范围和正文切片，然后构造既有 Finding / EvidenceSupport。长句或代码需要多个单位时选择多个 refs，不能拼接省略号或引用未展示的上下文。Finding ID 由宿主根据分支身份、claim 与支持范围确定性生成；重复提交不重复追加。同一批有非法引用或参数时整批拒绝，返回可修正的 validation 错误，不假装部分成功。

AgentExecutorState 和 ResearchTopicOutcome 增加默认空的 research_findings；每分支最多20项，保留不同或相互冲突的结论，不覆盖旧发现。达到容量后拒绝新增并诊断；不擅自丢弃已有发现。此字段是**原文引用合法的候选发现**，不是全局 accepted findings；有合法 ref 不代表 claim 已获语义认可。

研究过程中在下一次模型决策及时记录重要发现，不只在最后自由文本摘要里保存；一次记录可批量提交，与只依赖既有状态的工具同批。禁止引用同批尚未返回的读取结果或提前宣称新读取成功。record_findings 与其他本地更新按调用索引串行执行；更新后 checkpoint 保存记录和编号表，finalize 在受控退出时仍交付已有候选发现。

prepare_context 用现有分配器展示候选发现及来源摘要，不降低原始问题和约束优先级；候选被上下文省略时有诊断，不伪称当前模型仍看得到。登记表证明的是该分支先前实际展示过的范围，不代表所有历史原文都仍在当前模型上下文。

工具计量保持透明：每次 record_findings 计入现有 executed_steps；作为与 write_todos 同类的本地状态操作，不走外部 ToolGateway、不产生 Provider 调用，也不占现有 Gateway 24次入口额度。它受既有模型/分支轮数及20项发现容量限制，不新建预算服务。报告分别列 Gateway 调用、本地记录、待办更新及总 Agent 工具调用，不能把本地记录伪称网络检索，也不能把不同口径混作调用减少。取消或运行额度耗尽后不执行新的记录；已提交更新按 checkpoint 的原有事务边界恢复，不能承诺尚未提交的读取结果不丢失。

## 交接与补查：替换早期锚点优先，不叠加一套裁剪器

共享 evaluator 接收全局已接受发现、分支候选发现及读取轨迹。每来源仍最多3000字符、最多8来源、128引用单位，并保留现有 token allocator。材料优先级为：已接受发现的必要支持 → 候选发现的必要支持 → 围绕需求的相关读取单位 → 原有 query 回退。取消“按阅读时间从最早 anchor 花完全部额度”的主要选段路径；原 anchors 只作为无候选时的相关性回退与诊断。

必要支持复用全局并集预算分配，重叠不重复计费，不让可选上下文挤掉完整引用。来源竞争时按上述优先级选源，同级沿用稳定顺序，不因异步完成先后改变结果。真正超限则保留完整支持单位并报告丢弃，不切碎 quote、不扩大额度。

候选 claim 和它的全部 supports 必须一起进入最终模型输入；任一必要单位在来源、字符、单位或 token 分配中被丢弃，该候选不作为可评估事实展示，记录 omitted 原因。短 p 引用只映射最终实际可见的单位；n 引用不跨阶段使用。全局已接受支持也仍受最终原文可见性检查，不能通过候选笔记绕过该规则。

Evaluator 继续输出现有 coverage 和策略动作；只有原问题要求的操作、条件、限制等子义务全部被支持，才判对应需求 covered。待办关闭、发现数量、置信度或“有出处”不能替代这个判断。发现只覆盖一部分时给出具体缺口，用现有补查路由定位；不增加自动 Critic/重评循环或工具调用上限。

宿主校验来源、引用、需求 ID 和状态一致性；语义蕴含与子义务完整性仍由模型评估并经独立验收，不宣称字符串规则能保证语义正确。研究到上限仍缺失就 partial，保留真实错误和未完成待办。Writer 不把“未读到/未送达/未验收”写成“全部资料没有说明”。

## 兼容与组件边界

新字段默认空，新增状态类型显式注册 checkpoint serializer；旧 v3 checkpoint 可以加载并在新调用中建立登记表，不从历史日志补造已读短引用。当前 evidence_contract_version=3 不变：新增候选记录不改变全局 accepted support 的契约。原 v1/v2 的历史展示与继续研究限制保持不变。

修改落点：tools/evidence_read 与现有原文单位函数负责定位/切分；harness 工具边界、state/finalize/checkpoint 负责编号和记录；domain/research 负责结果字段；strategies/planning 与共享 evaluation_materials/evidence_evaluation 负责完整义务和交接。内部候选 draft/引用辅助逻辑可独立成一个小模块，禁止 harness 反向依赖三模式策略模块。复用纯引用解析逻辑时移动到共享底层，保留旧导入兼容，不复制三份实现。

保留公共回答格式、EvidenceStore 正文存储、租户与 URL 权限、长期记忆准入、取消/恢复优先级、模型尝试上限和 Provider 计量。不把候选发现自动写入长期记忆，不新增外部依赖、登录、插件或服务；不整体提交已有 dirty 工作树。

## 验收：先机制，再真实效果

离线使用 TDD：先观察正确断言失败，再实现。必须覆盖：

- find 命中/继续查找/无命中，中文、代码、非BMP字符与原文坐标一致；读预览完整 JSON 和既有范围/query 行为回归。
- 编号只对应实际展示原文；跨分支/租户、错版本/hash、未知 ref、隐藏文本、容量溢出拒绝；并发编号、重复记录和 checkpoint 重放确定性。
- 候选有合法引用但不蕴含结论时不能自动 covered；未完整回答操作条件时 evaluator 判缺口；同批未来读取不能授权记录。
- 关键事实在晚期阅读并记录后，能穿过三模式实际 evaluator 入口进入最终输入；早期无关 anchors 不能挤掉它。无笔记旧结果正常回退，候选全支持原子可见，真实超限仍保留 partial。
- 已记录后 iteration_limit/失败退出仍交付候选但不改退出原因；未提交更新不伪造恢复成功。Writer 只消费全局已验收发现，Answer/Report 分开回归。
- 完整后端 not-real、独立 Ragas 回归、相关文件 lint/格式及五轴代码自审；不靠脚本 evaluator 的正确答案冒充真实模型效果。

实施完成后先冻结源码留样、配置与评分器，登记唯一运行目录；不重跑挑分、不补评分、不修改旧批次。沿用最近批次：doubao-seed-2.0-lite、temperature=0、研究输出4096 token、Answer 2000字符、长期记忆关闭；每运行40逻辑调用/80 Provider/24 Gateway工具入口/12分支轮/360秒。记录工具保持上文说明的本地操作口径，不增加这些上限。增加本地记录带来的调用和轮数开销必须如实统计，不能保证总调用下降。

真实验证分两批独立登记，均一次三模式：

1. **可比 dev 回归：** 同3题、7篇冻结官方资料，共9条 Answer；整批研究最多360逻辑/720 Provider，隔离 Ragas0.4.3 原裁判配置最多144 Provider。对应唯一目录 tmp/grounded-handoff-real-answer-20261003 及其 -quality、-comparison。它是真实模型 API，但不是生产联网检索验收；与旧分只做描述性对照，没有新 baseline 时配对 n=0、delta/CI=null。
2. **真实联网端到端：** 一道未放入运行提示或离线测试夹具的公开官方资料题，三模式各一次。付费前固定题面、参考要点、来源和验收项，研究端只得到用户问题，不得到 gold；通过项目配置的真实 search/fetch/read 链路，不替换本地语料。整批研究最多120逻辑/240 Provider，原 Ragas评分最多48 Provider；唯一目录 tmp/grounded-handoff-live-answer-20261003 及其 -quality。若真实搜索/抓取配置不可用，记录阻断，不自动切成冻结语料宣称通过。

两批合计上限960研究 Provider、192评分 Provider，非预计花费；本次写规格不调用付费 API。目录若已存在则先报告，不能静默改名整体重跑。付费前核对实际配置和价格可用性，不输出密钥。

报告全部状态、非空答案、Factual F1/Faithfulness/Goal、评分有效覆盖/NA/error、逻辑与 Provider 调用/token、工具类别、已读→已记录→评估可见→Writer可见的流失及原因。联网批另核验实际搜索结果、真实抓取 URL、引用可访问性、关键操作和条件是否完整；自动检查与代理人工式审阅分开，不能称为独立人类盲审。

上线可靠性不以三题一次或 Faithfulness=1 认定。验收成功至少要求机制回归通过、联网链路真实执行、P&E 回答覆盖预登记关键要点且引用支持成立；另两模式如实报告，不因完成状态就宣称质量达标。质量未改善、开销明显上升或指标分歧时继续定位；后续未见测试集、重复运行和独立裁判/人工校准另行登记，不改本批原始结果。
