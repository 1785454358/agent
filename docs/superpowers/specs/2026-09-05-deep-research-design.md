# Deep Research：Plan-and-Execute + ReAct

用户已确认架构并要求实施。保留 Basic 的固定三节点图，新增 `deep` 模式。

## 执行约定

Planner 通过原生工具调用提交研究任务（ID、目标、完成条件、依赖）。
Planner 和 Replanner 仅绑定 `submit_plan` 工具，不传 `tool_choice`，以兼容
拒绝强制工具选择的思考模式接口。仍要求返回一个合法的 `submit_plan` 调用，
普通文本及无效计划最多尝试两次；失败后明确进入规划失败处理，不跳过校验。
执行器使用模型原生 tool_calls 运行 ReAct，工具为 search_web、fetch_page、
search_memory、finish_task。一个任务可有多轮行动，一轮独立读工具可并行；
第一版任务按依赖顺序调度，共享已读资料和任务状态。

任务反馈含完成/受阻状态与缺口，已读资料独立保存在共享工作状态。受阻、有缺口，或本轮计划全部
执行结束时，由 Planner 检查是否替换剩余计划或结束。已完成任务不丢失；
验证任务 ID、依赖、循环依赖与总任务上限。重规划最多两次。

## 记忆与报告

工作记忆是计划状态、已执行查询、已读页面及工具结果，不保存 ResearchNote、
Claim 或 Evidence。长期记忆复用现有页面 JSONL；开启后按 BGE 语义检索，
返回 URL、标题、抓取时间，默认排除超过七天的缓存。近期事实仍需网络核验。
Writer 使用已读取且有效的原文上下文，复用现有数字标题和编号引用格式。
缺口仅作为局限说明，不将模型任务反馈当作事实来源。

## 边界与可观察性

默认至多六个已执行任务、每任务四轮、全局十二轮 Executor、两次重规划，
共三十次研究工具调用（含失败及缓存命中，控制工具由决策轮次约束）。
根据用户 2026-09-05 最新要求，不设总时长、累计 Token 或费用预算，旧配置
不再触发停止。达到次数上限仍调用 Writer；只保留单次请求故障超时。
时间、各角色 Token 及工具调用数仅用于观测。重复成功调用返回缓存，失败允许
有限重试；无进展、无效参数、无工具调用均占用轮次，不能无限循环。
无来源、未解决任务、次数上限终止及 Writer 降级返回 partial，不能伪装成功。
取消传播到异步调用。Provider Token 分 Planner、Executor、Replanner、Writer
累加；超时未返回的用量无法准确统计，展示值仅为 Provider 已报告值。

API 接受 mode=basic|deep，默认 basic；CLI --mode deep；页面可选择模式。
事件展示计划、任务、工具选择/执行结果、重规划、局限、总耗时和用量，
不要求或展示模型隐含推理。模式随运行记录持久化。

## 验收

离线脚本模型驱动真实协调器和工具层，验证自适应补搜、失败恢复、计划
依赖与重规划、语义记忆、次数上限/取消、全部角色用量和 Basic 兼容性。
真实模型仅做少量工具调用的冒烟，不将脚本模型测试当作真实研究质量评测。
