# Harness 面试资料重构设计

## 目标

将现有偏源码说明书式的材料重构为适合 Agent 后端工程师面试的学习体系，使读者能够：

1. 用一句话和 90 秒说明 Harness 的价值；
2. 从核心问题出发解释模块，而不是机械背模块名；
3. 区分成熟生产架构、当前项目实现和后续演进；
4. 使用统一模板回答常见问题，并能承接二到三层追问；
5. 在面试前 30 分钟完成一次高密度复习。

## 现状判断

现有资料技术覆盖完整，已经包含 LangGraph、策略子图、Agent 执行器、Tool Gateway、Evidence、Memory、Checkpoint、Ledger 和分布式运行等内容。主要问题是：

- 内容按源码模块展开，缺少从工程问题到设计方案的主线；
- 42 道问答权重相同，不利于临近面试时取舍；
- 部分段落将当前实现、成熟架构和未来规划连续陈述，容易在面试中说过界；
- 简历要点过长，单条同时包含多个设计决策，招聘者难以快速抓住亮点；
- 安全、人工审批、评测、版本治理、取消与背压等生产级主题需要补强。

## 采用方案

采用“新增速记主线、保留源码参考、定点修改简历”的混合方案。

不整体覆盖现有长篇资料。新增一份独立的 Harness 面试速记手册，作为主要背诵入口；现有架构图、源码导读、长期记忆专题继续作为深入追问参考。同步精简简历项目材料，并更新阅读目录以建立清晰入口。

这样既保留已有技术细节和未提交修改，也能避免面试者在大量材料中失去主线。

## 内容模型

### 从问题出发

速记手册先回答 Harness 为什么存在。核心问题固定为：

1. 如何限制 Agent 的自主边界；
2. 如何让不同策略共享运行协议；
3. 如何划分可恢复状态与运行依赖；
4. 如何治理模型和工具调用；
5. 如何控制上下文、Token、费用和并发；
6. 如何管理证据、引用和记忆；
7. 如何处理重试、幂等、恢复和部分成功；
8. 如何抵御不可信输入与 Prompt Injection；
9. 如何观测、审计和复现一次运行；
10. 如何通过评测和版本管理安全迭代。

### 模块划分

十二个模块分别是：接入契约、路由器、状态与 Runtime Context、策略注册与子图、Agent Executor、Model Gateway、Tool Gateway、Evidence Store、Memory、Context/Budget Manager、Checkpoint/Ledger/Runtime、Observability/Evaluation。

每个模块统一回答四个问题：

- 它解决什么问题；
- 它负责什么；
- 它不负责什么；
- 当前项目如何实现或尚缺什么。

### 三层事实口径

所有可能引发追问的主题使用三个标签：

- **成熟模式**：生产系统通常应该具备的设计；
- **项目实现**：仓库中已经存在且可以用源码或测试验证的能力；
- **演进方向**：合理但尚未完成的方案，面试时必须使用将来时。

简历正文只写“项目实现”。速记手册允许讨论全部三层，但必须显式区分。

## 问答模板

每道核心问题采用可逐级展开的结构：

1. **一句话结论**：10 秒内直接回答；
2. **标准回答**：约 30～60 秒，使用“问题—设计—原因—边界”；
3. **项目落点**：说明 DeepTrace 中的具体模块；
4. **追问准备**：列出一到两个常见追问和关键答案；
5. **禁区**：指出不能承诺或不能混淆的概念。

答案以理解和复述为目标，不追求逐字背诵。术语第一次出现时给出中文解释，后续保持名称一致。

## 简历改写原则

简历保留五条核心要点：

1. 统一 Harness 与策略插件化；
2. 受控 Agent 循环与工具治理；
3. Evidence、引用与上下文治理；
4. 记忆体系；
5. 持久化与可靠性。

每条控制为一到两行，不罗列所有内部类名，不使用无法证明的性能百分比。评测、安全和可观测性若当前实现不足，只放在可选要点或演进方向，不写成简历既成成果。

## 一致性和真实性规则

- 以当前仓库源码和测试作为“项目实现”的证据；
- 不把设计文档中的规划自动视为已完成能力；
- 不承诺任意外部副作用 exactly-once；
- 不把 Checkpoint、Memory、Evidence、Cache 和 Ledger 混为一种存储；
- 不声称 Multi-Agent 一定比单 Agent 或 Plan-and-Execute 更好；
- 不声称仅靠 Prompt 就能保证安全、引用正确或结构化输出；
- 成熟模式中新增但项目未实现的能力，统一标记为“演进方向”。

## 验证方式

完成改写后进行以下检查：

1. 检查 Markdown 链接和目录入口；
2. 搜索“已实现”“支持”“保证”等强断言，逐项核对源码或降级表述；
3. 对照简历、90 秒介绍和高频问答，确保术语与架构口径一致；
4. 检查二十道核心问题是否覆盖状态、工具、记忆、可靠性、安全、观测和评测；
5. 检查每个核心答案能否在 60 秒内口述完成；
6. 仅修改目标文档，不覆盖仓库中已有的其他未提交修改。

## 非目标

- 本次不修改 Harness 业务代码；
- 不为了匹配成熟架构而虚构项目能力；
- 不删除现有完整问答和源码导读；
- 不制作 Word、PDF 或演示视频；
- 不提交或整理与面试资料无关的工作区改动。
