用户在“先选段 / 先引用编号 / 同时修改”中确认 A，回复“开始”。本轮只改善来源选段，不改引用输出契约、逐字匹配、回答提示或评分。主验收仍为 P&E + Answer，另测 Workflow、Multi-Agent。具体规格待用户审阅后进入实施计划。

## 已复现问题与假设

上一轮 minimal-plan-real-answer-20261003 的单跳 P&E 选段可在相同冻结正文、原问题与 requirements 下完全复现：四段范围为 839:1105、1671:2837、4139:4911、22301:22942；thread_id 必需性说明实际位于约 3679 字符附近，却未送达评估器。当前稀有词总分排序、固定窗口与前后 120 字符扩展会选中半段，并让一项需求挤占另一项空间。

另一个独立失败是版本题 494 字符 quote 把原文换行改为空格，逐字匹配失败；此轮不修。相关既有回归 47 项通过，说明真实失败尚未被这些用例保护，而不是可以跳过新的回归。

假设：保留适合预算的结构块，并分别考虑固定答案要点，有助于把关键事实送达模型。它不是语义检索/蕴含保证，也不保证事实得分或 completed 提升。

## 组件与数据流

生产修改限于 tools/evidence_views.py 的选段逻辑，以及 strategies/evidence_evaluation.py 传入固定答案要点；不新增框架层。共享 selector 仍被 read_evidence、评估器和回答材料复用，responses/excerpts.py 保持兼容别名。

为 select_source_excerpt、select_evidence_passages、select_supported_passages 添加可选 keyword-only 参数 focus_queries，默认 None，原有调用可继续工作。评估器传入封存 requirements 的 description（现有最多 6 项），不再仅把多个要点拼成一个词项集合；完整原问题仍传入，不替代问题、用户约束或事实契约。工具与回答侧未传 focus_queries 时按原问题选取。

### 结构候选

1. 短文在既有 limit 内仍原样返回。长文按空行识别原始段落；900 字符内的段落作为完整候选，不再固定向相邻段落扩展 120 字符。只使用原始字符范围，不改写空格、换行、标点、Unicode 或 Markdown。
2. 超过 900 字符的段落优先在句末标点或行边界拆为有界块；代码/列表可按原始行边界分块，不在正常块中截断一个可容纳的句子或行。完成事实块选择后，邻近标题可作为单独完整上下文，在实际剩余额度允许时保留，不吞掉事实空间。
3. 无句界/行界的超长文本或单个单位仍超过可用空间时，允许原有有界窗口/前缀式回退；保留已有省略说明和 strategy/ranges。极小额度也按原有有界回退处理。结构识别只是启发式，不是完整 Markdown/自然语言解析器，不能声称所有片段均完整。

### 均衡与预算

1. 复用现有词项抽取、停用词和文内稀有度权重，不新增 embedding、reranker、特定主题词表或 LLM 调用。
2. 第一轮按 focus_queries 的既有顺序，为每项选择最相关且还能完整放入额度的候选；同一个候选只加入一次。若该项最高可用候选已包含于选段，复用该范围，不为凑数再选一个。匹配词项不等于事实被覆盖，不修改 CoverageAssessment。没有匹配或放不下时跳过，不生成替代事实。
3. 然后按完整原问题的相关性填充剩余空间；平分按原文位置，合并重叠范围，最后按原始位置展示。不是每项硬切 1/N 额度；只是在整体额度内避免单一要点先耗尽全部空间。每来源均衡，不新增跨来源调度器。
4. 保留现有候选段数上限 min(16, max(1, limit // 600))，实际序列化的行号/范围/省略说明计入 SourceExcerpt.limit；不得仅检查正文长度。评估每来源仍为 3000 字符，最多读取 8 份来源；原有工具预览 JSON 限额和 token allocator 继续生效。
5. select_supported_passages 仍优先保留已验收的原文 quote，按现有规则使用剩余额度再选块；不修改已验收 quote 的位置或正文，不给已有支持重新判语义真假。已验收支持的原有上下文边距逻辑保留，本轮结构规则用于新选候选。

## 兼容、失败与排除

EvidenceStore 正文/哈希、EvidencePassage 字段和稳定 ID 算法、EvidenceSupport 与 checkpoint schema 不变；新范围导致新 passage_id 是预期行为，历史支持继续按版本/哈希/原坐标验证。明确 start 的 read_evidence 范围读取不改；查询读取复用新候选。

不匹配仍回退有界前缀，空文仍无伪造位置；非法 limit/参数仍拒绝。单个来源不可读不影响其他来源，token 分配仍按整块保留或丢弃评估片段，掉落/隐藏段不能用于支持。保留真实 visibility 事件与原始问题固定上下文，事件失败仍隔离。

不改 budget、重试、工具权限、抓取 20000 字符上限、来源顺序/8 来源上限、三模式路由、补查去重、待办提示、规划、记忆、SupportDraft/resolve_support、语义门禁、回答/缺口措辞、模型或 Ragas。尤其不做空白归一化接受 quote、不把选段命中写成 coverage=covered，不读取 gold/期望引用/期望 URL 做选择，不对三道题硬编码。

省略提示和可见范围不是文档完整性证明；本轮仍可能出现错误缺口声明。抓取时已丢失的尾部无法由 selector 找回，生产联网端到端需另行验证。
