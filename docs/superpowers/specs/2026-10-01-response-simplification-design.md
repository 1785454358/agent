# Harness 简化：响应生成收敛设计

日期：2026-10-01。状态：用户确认后已完成响应生成收敛；三项独立实施，本文件定义第一项的可独立验收改动。实际验收见对应实施计划。

## 目标

将响应生成从多条可叠加的纠错路径，收敛为一条有界流程。减少模型调用、重复解析与嵌套分支，保留引用校验、上下文预算、确定性降级和现有公开接口。

验收不以拆出更多文件或增加抽象层为目标：删除旧的独立纠错控制路径，共用解码实现，不新增服务类、策略注册器或纠错框架。

## 范围和顺序

1. 当前改动：响应生成收敛。
2. 独立后续改动：迁移旧 Topic 图的测试与公开入口；生产研究路径以 Shared Agent Loop 为准。不能直接删除仍有消费者的实现。
3. 独立后续改动：记忆入口收敛、证据批量核验与非主链路逻辑整理；保留版本、遗忘、来源核验和上下文预算。

不修改数据库、Runtime、部署模式、依赖版本、认证或前端。

## 已检查的现状

- `responses/graph.py` 内有独立的消息文本解码，重复了 `harness/model_io.py` 的职责，而且没有同等处理模型消息 content blocks。
- generate 节点分别处理不可解析、零引用和超长 / 悬空句，每条都可以再次调用模型；单个候选可能先后触发不同纠错。
- evidence 正文目前在 generate 开始时加载一次，纠错复用材料。这一正确行为保留。
- 三个响应模式已经共用 ResponsePolicy 与同一图拓扑，没有必要重建模式框架。
- 用户在 `responses/citations.py` 与对应测试中有未提交修改。本次保留，不覆盖、不纳入提交。

## 方案比较

### 采用：统一现有流程

复用公共消息解码，保持现有内容 JSON 契约；对首次候选一次检查格式、引用标记、篇幅与完整性，合并为一次纠错请求。

优点是能直接减少控制路径，不改变 Provider 调用协议，适合当前多种兼容接口。缺点是还需要少量 JSON 解析兼容代码。

### 不在本次采用：同时接入 Provider 结构化输出

原生结构化输出可以减少格式解析问题，但需要验证实际 Provider / 模型的支持方式，并调整 Gateway 协议和相关测试。未经验证直接切换，会将接口兼容和故障回退复杂度带入这次简化。

因此本次不新增 schema 能力探测、Provider 切换或结构化输出配置。以后单独验收该能力，不把它混入当前流程收敛。

## 最终流程

```text
加载证据
  → 首次生成并解析候选
  → 一次检查候选问题
  → 无问题：直接采用
     有问题：合并要求，至多一次纠错生成
  → 对选中候选做确定性篇幅处理
  → 既有引用校验
  → ResponseOutcome 或证据清单降级
```

一次 generate 执行最多两次调用 ModelGateway.invoke：首次生成与一次纠错。Gateway 自己的 transport retry 仍由 Gateway 管理，不计入上述业务纠错次数；Checkpoint 重放也不宣称跨执行全局至多调用两次。

### 解码和解析

- 删除响应模块重复的 `_payload_text` 实现，直接使用 `harness.model_io.payload_text`。
- 保留局部 `_extract_content` 的业务契约：JSON 对象的 content 必须是字符串，最终正文不能是空字符串。
- 保留既有“散文包裹 JSON 对象”兼容行为，不增加 json-repair 或另一套解析器。
- 支持真实 AIMessage 的字符串与文本 content blocks，复用已经存在的公共实现。

### 候选检查与一次纠错

首次候选检查的问题只有四类：

1. 无法解析或正文为空。
2. 正文没有引用标记。
3. 正文超过该 ResponsePolicy 的 max_content_chars。
4. 正文以明确悬空标点结束。

对所有发现的问题生成同一段纠错要求；纠错后不再进入第二条模型修复路径。问题集合用简单数据表示，不引入新的候选状态机或复杂模型。

本次不改变未知引用的业务判断。是否支持引用仍由现有 validate_citations 决定，不把字符串格式合规等同于证据真实性。

### 候选选择与确定性处理

- 纠错生成得到可解析、非空正文时，以纠错候选为准。
- 纠错因解析 / 格式错误失败时，保留首次可解析候选；首次候选也不可用时，走现有 generation_failed 降级。
- 最终候选超过篇幅上限时，按现有句子边界规则截断，不再调用模型。
- 最终候选仍有悬空结尾时，保持既有 incomplete 观测信号；不声称仅靠标点判断已经验证了内容完整性。
- 最终正文无受支持引用时，按既有规则返回可追溯的来源清单与 partial reason。
- Transport / Provider 错误不伪装成解析错误；取消继续传播。

## 保留的不变量

- ANSWER / BRIEF / REPORT、构图入口、ResponseInput / ResponseOutcome 字段保持兼容。
- `load_evidence → generate → validate` 节点名与 Checkpoint 边界保持不变。
- 全部模型调用经过 ModelGateway，并保留 system instruction、原始任务、当前约束。
- evidence 正文只在局部使用，不复制进可恢复 State。
- context token 预算、纯文本格式处理、引用校验和 partial 降级保留。
- 预算裁剪与输出截断观测继续记录；正常纠错成功的短正文不误报截断。

## 验证

先补行为回归并确认当前失败，再实现最小流程：

- 首次候选同时无引用、超长和悬空，只纠错一次。
- 首次解析失败，纠错候选仍超长，最多两次业务调用并确定性截断。
- 首次无引用，纠错候选仍无引用，最多两次调用并返回来源清单。
- 纠错解析失败时保留可用首稿，不产生第三次业务调用。
- AIMessage 文本 content blocks 正确解析为正文。
- 首次候选合格时只调用一次；无证据时不调用模型。
- 既有篇幅、纯文本、引用、跨 workspace 证据、预算与 Checkpoint 测试继续通过。
