# ResearchPilot 简历项目描述设计

## 1. 使用目标

面向字节跳动、阿里巴巴等公司的大模型应用开发与 Agent 开发校招岗位，将 ResearchPilot 写成一段适合一页中文技术简历的个人项目经历。内容需要让招聘者快速看到 Agent 架构、复杂任务执行、工具使用、多 Agent 协作和工程实现，同时保证每项表述都能由当前代码、测试或运行记录支持。

## 2. 篇幅与结构

项目经历采用以下固定结构：

- 项目名称与个人项目身份。
- 两行项目简介，说明产品目标与完整研究流程。
- 一行技术栈。
- 五条技术要点，每条先写解决的问题，再写采用的技术和形成的能力。
- 另附一段面试口述版本，不直接占用简历正文。

公开 GitHub 地址暂不写入正文，待代码整理并推送后补在项目名称旁。

## 3. 简历信息优先级

### 3.1 多模式 Agent 架构

明确区分三种模式：

- Basic 使用固定 Workflow，执行一次规划、并行检索与报告生成，面向快速研究。
- Deep 使用 Plan-and-Execute，Planner 拆解任务，ReAct Executor 调用工具，并根据执行反馈动态重规划。
- Multi-Agent 使用 LangGraph 编排 Supervisor 与多个 ReAct Researcher，支持并行研究与缺口补查。

该项是项目最主要的辨识度，应放在第一条。

### 3.2 任务规划与复杂问题求解

写清任务拆解、完成条件、任务依赖、执行反馈和动态重规划。避免只列 Planner、Executor、Supervisor 名称，应说明这些组件如何推动研究从问题走到报告。

### 3.3 ReAct 工具调用与研究上下文

写明 Agent 能自主选择网页检索、正文抓取和历史资料检索工具，并根据工具结果继续研究或结束。BGE-M3 从网页正文筛选相关原文，Writer 使用原文生成带顺序引用的报告。长期记忆、缓存和时效控制可以合并在这一项，不单独占一条。

### 3.4 Supervisor Multi-Agent 协作

写明 Supervisor 分派互斥研究方向，多个 Researcher 限并发执行，并根据未解决叶子缺口生成定向补查任务。检查项绑定、结构化收尾、异常降级等属于面试展开内容，不在简历正文堆砌内部字段名。

### 3.5 性能与成本控制

当前简历只写已经实现的优化手段：并行 Researcher、本地 BGE-M3 筛选、上下文长度限制、请求缓存、单飞复用、终止短路与定向补查。措辞使用“减少重复检索和无效调用”“控制耗时与 Token 成本”，不写未经统一评测验证的百分比。

项目后续增加固定评测集后，可以将本条替换成量化结果。量化表述必须同时包含基线、优化后结果、样本规模与质量约束，例如平均耗时、平均 Token 和来源覆盖率，不能只挑单次运行数据。

## 4. 工程可信度

FastAPI、SSE、Pydantic、运行记录、按角色统计耗时和 Token、自动化测试等内容用于证明项目可以运行和验证。正文不单独写“额度控制、异常降级、可观测事件”，可以在第五条末尾或面试口述中简短提到。目前可以使用“210 项自动化测试通过”，因为该数字来自最新全量测试。

## 5. 事实边界

可以写入当前简历的事实包括：

- 个人独立开发。
- Basic、Deep、Multi-Agent 三种平级研究模式。
- LangGraph、Plan-and-Execute、ReAct、Supervisor Multi-Agent。
- 搜索、网页抓取、历史记忆与本地 BGE-M3 原文筛选。
- FastAPI、SSE、Pydantic 和 OpenAI-compatible Provider。
- 并发执行、缓存复用、终止短路、定向补查与带引用报告。
- 210 项自动化测试通过。

暂时不能写入的内容包括：

- 未经固定评测集验证的耗时或 Token 降幅。
- “达到生产级”“显著提升准确率”“超过 GPT-Researcher”等比较结论。
- 尚未完成的公开部署、真实用户规模和线上可用性指标。

## 6. 后续项目改进

简历竞争力最高的下一步是建立研究评测集。使用固定问题分别运行 Basic、Deep 和 Multi-Agent，多次记录来源覆盖、事实正确性、报告完整度、墙钟耗时和 Token，形成可复现的质量与成本对照。完成评测后再更新简历第五条，不把计划中的能力提前写成已经实现。

## 7. 成稿标准

- 两行简介能够说明项目用途和完整闭环。
- 技术栈只占一行，不重复技术要点。
- 五条要点均以动作和结果为主，避免纯技术名词罗列。
- 首条必须明确 Basic 是 Workflow。
- 至少一条体现 Plan-and-Execute 与动态重规划。
- 至少一条体现 Supervisor Multi-Agent 和并行 Researcher。
- 成本优化不使用未经验证的数字。
- 自动化测试数字准确写为 210。
- 提供一版可直接粘贴的简历正文和一版约一分钟的面试介绍。
