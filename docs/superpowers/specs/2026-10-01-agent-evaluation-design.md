# Agent 评测：单框架、可复现、面向 Harness 的方案

日期：2026-10-01。状态：设计提案，待用户确认；尚未安装或接入 Ragas。

## 目标

回答三个问题：Agent 是否把任务做对，执行过程是否合理，Harness 的可靠性与记忆机制是否带来可测收益。不是用几个漂亮分数证明项目已经成熟，也不把工程回归或脚本模型的满分称为真实模型质量。

沿用项目现有 eval runner、冻结语料、三模式矩阵和报告结构。评测在应用层之外运行，不新建运行时、评测服务或看板。

## 现状与缺口

现有代码已有 JSONL 题集/语料、真实工具治理边界、故障注入、调用计数、Markdown 报告及五维自定义 LLM judge。它们是可保留的基础，不需要推倒重写。

具体缺口：题集仅 3 题；缺少真实决策轨迹；没有同预算简单基线；completed 由研究 reason 推断，而不是应用终态；来源 ID 合法性不能证明引用支持结论；judge 失败成为 None，汇总默认 0 容易混淆未测与差分；没有记忆的多轮评测；模型 Token 与费用尚未采集。

本轮真实 smoke 进一步揭示预算敏感性：3 个研究分支各 3 轮，均在 write_todos、search_web、write_todos 后退出，未 fetch_page；最终 partial/no_sources、11 个研究执行步骤。API 搜索正常不等于研究完成，规划辅助动作也消耗执行轮次。

## 选型比较

1. **推荐：Ragas 唯一主框架 + pytest 工程回归。** Ragas 提供工具调用和任务目标评测，也可评测答案事实与证据一致性，项目只需一个适配层；保留本地 JSON/Markdown，不强制云账号。采用官方当前推荐的 collections API，实施时固定验证过的版本，作为可选评测依赖，不侵入生产依赖。
2. **备选：AgentEvals + 现有答案 judge。** 与 LangGraph 消息结构贴合，适合确定性轨迹匹配；若使用 LangSmith 可增加实验管理，但没有必要将云上传设为默认。缺点是答案质量仍需另一套独立评测实现。
3. **不推荐仅扩充自定义 judge。** 依赖少，但量表、解析和校准继续全部自行维护，不满足优先采用成熟体系的诉求。

官方依据：[Ragas Agent metrics](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/agents/) 提供 ToolCallAccuracy、ToolCallF1 和 AgentGoalAccuracyWithReference；[AgentEvals 官方指南](https://docs.langchain.com/langsmith/trajectory-evals) 区分确定性轨迹匹配与 LLM 轨迹评审。这里只选择一个主框架，不同时接入两套。

## 评测维度

| 维度 | 首版指标 | 输入与边界 |
| --- | --- | --- |
| 工程可靠性 | 终态一致性、租户隔离、恢复不重复执行、限额与取消 | pytest + 现有真实组件；不交给 LLM 判断 |
| 任务达成 | AgentGoalAccuracyWithReference | 问题、观察到的消息/工具结果、人工参考目标；与 runtime completed 分开 |
| 工具执行 | ToolCallAccuracy / ToolCallF1 | 实际工具名、参数、参考调用；严格顺序仅用于必须有序的任务 |
| 答案事实 | FactualCorrectness，F1 模式 | 回答与人工参考答案；无参考则未测，不伪造分数 |
| 证据忠实 | Faithfulness | 回答与实际取回的证据片段；非“存在引用 ID”即通过 |
| 效率 | model/tool 调用、研究步骤、耗时分位数 | 原始实测计数；Token/费用未接通时为 null |

[Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/) 用回答声明与取回上下文的一致性衡量证据支持；[FactualCorrectness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/factual_correctness/) 对照参考事实。二者不能互相替代，也不能自动证明每个引用 marker 与对应来源的逐项语义关系。引用精确度仍保留抽样人工核验，不将 ID 子集检查改名为语义准确率。

## 最小实现结构

保留现有 dataset/env/runner/scoring/report。仅新增两个集中模块：

- `eval/trajectory.py`：记录模型输出中的工具请求及实际工具执行结果，保留 caller、分支、顺序、拒绝/失败类型；转成 Ragas 消息。多分支按分支保存再作确定性汇总，不把并发调度顺序硬编码为唯一正确路径。
- `eval/ragas_evaluator.py`：映射已有样本、调用框架指标、记录 evaluator/version、value/reason/error、judge 模型与 prompt 版本。缺少可选依赖时显式拒绝该命令，不静默退回自定义评分冒充 Ragas。

运行记录直接消费 ApplicationRunResult.status/reason/steps/gaps，研究与回答状态另存；模型计数不由 steps 推算。工具请求不等于成功执行，失败与被治理层拒绝的请求不能被过滤掉。语料 search/fetch 与生产工具的区别写入报告。

旧自定义 judge 可继续通过原开关运行；分数标识 legacy_custom，与 Ragas 0–1 指标分栏，不能把原 1–5 量表自动归一化成框架指标。默认仍为无网络的确定性回归。

## 题集与记忆专项

冻结首版研究题集 12 题，6 类各 2 题：单跳事实、多跳对比、来源冲突、信息不足、无关噪声、时效边界。每题必须有人审过的参考答案、关键事实、证据来源、必要工具约束与分类；优化集 6 题和保留集 6 题分开，报告分栏，不把保留集用于 prompt 调优。

另设记忆场景 6 组：用户偏好续聊、同线程证据复用、同用户跨线程召回、跨租户不可见、过期/冲突记忆不误用、记忆缺失时可退化。每组有明确的前置写入/时间/命名空间和后续问题。

隔离、状态与 TTL 使用确定性断言；答案目标另用框架质量评测。memory on/off 共享题目、模型、预算和初始语料；多轮场景允许组内连续，组间清空数据，禁止把评测参考答案写入被测记忆。仅在专用语义检索验收中覆盖 Chroma/BGE-M3，不把 lexical 结果推广为语义记忆效果。

## 基线、消融与报告

先实现一个 search → fetch → answer 的简单基线，与 Workflow 共享语料、回答模型、预算上限和指标，回答“额外 Agent 机制带来了什么”。基线不读取 gold answer，主模型不获知参考事实。

三模式比较只在研究题集上；记忆 on/off 是独立场景比较。首版不加入几十个开关或同时拆除多个 Harness 机制的消融。故障注入另列恢复成功率、重复外部执行次数和未完成率。

报告包含逐题结果、适用/未适用/失败样本数、分类均值、重复间波动、p50/p95 延迟与调用数。LLM judge 的错误为 null + error，不算 0、不藏到成功均值里；必须同时报告覆盖率和被测系统失败率。系统失败保留原始记录，运行矩阵继续后续题，程序退出码反映失败。

不采用一个加权“总分”掩盖维度差异。先用固定题集做回归差异，再经人工抽查设质量阈值；不先宣称 0.8 就是行业合格线。3 题或单次真实 smoke 不用于显著性结论。

## 真实评测预算与安全

安装/离线适配验证不调用真实 API。之后先 1 题 Workflow 对比简单基线、每系统 1 次，随后对这两份已有回答评分，不因 judge 失败重跑 Agent。

开始前展示被测调用和 judge 调用的独立上限：被测每系统最多 12 次逻辑模型/12 次工具、每调用最多 1024 输出 token、每系统 180 秒；judge 总计最多 12 次逻辑调用、每调用最多 1024 输出 token、总计 180 秒。预算控制必须包住 SDK 的实际 LLM 调用，不能将一次指标调用误称一次模型调用。传输重试单独记数；没有价格信息不承诺美元上限。

本轮 3 轮限制已证实不足；下一次真实验收建议每研究分支最多 6 轮，仍受上面的总逻辑调用上限约束。这是后续调整建议，未在本次真实测试偷偷提高上限。更多题/模式/重复次数运行前展示计划调用量并约定规模。

judge 独立配置与预算；缺少独立 judge 配置时显式记录是否与被测模型相同，不称独立评审。人工抽检至少覆盖错误、冲突和低分样本。每次记录 dataset/corpus 哈希、Git revision/dirty 状态、框架版本、模型与预算；缓存评分时完整包含这些身份，不能复用旧模型结论。

默认关闭云追踪，不上传项目源码、密钥或历史用户记忆。外部文本与被评回答作为不可信评分数据，不能覆盖评测指令。只发送限定长度的公开题目与必要证据；截断和缺失必须在报告中注明。

## 验收与实施顺序

1. 测试先行，补状态/缺失指标/错误报告的回归；实现最小轨迹记录与真实 Ragas 工具指标。用正确调用、错误参数、缺失工具、额外工具、并行工具案例验证评分有区分度，不仅验证 SDK 能导入。
2. 适配答案指标；框架契约测试与真实 judge 验收分开，前者不冒充真实质量测试。确定性测试不请求网络。
3. 加入简单基线、冻结研究题集和 6 组记忆场景，输出对照报告；原有用户评测资产保留。
4. 按明确限额运行首轮真实小样本与 judge，记录全部失败与未知项，再讨论扩容。
