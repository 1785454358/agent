# Supervisor 终止短路与报告结构设计

日期：2026-09-06

## 1 背景与问题

运行 `68891660c219` 已完成初始 r1/r2/r3 和补查 r4/r5。第二次重规划发生时，主管轮次已经耗尽，系统不再允许派发新任务，但仍调用了 Supervisor。模型两次返回无法通过 `SupervisorDecision` 校验的工具参数，产生 `invalid_arguments`、一次修复和确定性降级。由于路由结果已经被硬上限决定，这两次模型调用没有改变执行结果，只增加了延迟、Token 和异常事件。

同一次运行的报告包含分主题正文和局限说明，但缺少开头总述、章节之间的承接以及正文末尾的综合结论。来源列表使用“参考文献”，与网页新闻、机构页面等混合来源的实际性质不符。

## 2 目标与范围

本次修改只完成三件事：

1. 在研究结果已经可以由任务表和硬边界确定时，不再调用 Supervisor。
2. 用一次 Writer 调用稳定生成带总述、主题分析、必要局限和综合结论的完整报告。
3. 中文报告末尾的来源区标题由“参考文献”改为“参考内容”。

不增加 Critic、Editor 或第二次润色调用，不调整 Researcher 轮数、工具额度、Token 统计方式和 Basic、Deep、Multi-Agent 的总体架构。

## 3 Supervisor 终止短路

`replan_node` 在调用 Supervisor 前按以下顺序检查持久任务表和执行边界：

1. 补查批次没有新增来源且仍有叶子缺口时，以 `stagnant` 结束。
2. 没有未解决叶子缺口时，直接标记 `completed` 并进入 Writer。
3. 研究员总数已达到上限时，以 `researcher_limit` 结束。
4. 剩余网络额度不足两次时，以 `global_tool_limit` 结束。
5. 已没有可用于派发后续任务的 Supervisor 轮次时，以 `supervisor_round_limit` 结束。
6. 只有仍有叶子缺口并且研究员、网络额度和后续轮次都允许补查时，才调用 Supervisor。

Supervisor 在可行动阶段返回无效结构时，仍保留一次格式修复；再次失败则按叶子缺口生成确定性补查。Provider 超时仍只调用一次并打开运行内熔断。这样既保留模型对“如何补查”的判断，也避免在结果已经确定时做无意义的最终评审。

## 4 Writer 报告结构契约

Writer 继续直接接收网页正文或 BGE 筛选出的原文、来源目录、研究问题、当前日期、时区和终止原因，不引入 `ResearchNote`、Claim、Evidence 或额外摘要对象。

中文报告正文必须遵守以下结构：

```text
报告标题

1 总述
用两至三段直接回答研究问题，概括核心发现、主题之间的关系和总体趋势。

2 ...
2.1 ...
按问题自然形成主题章节。每个一级章节先用一段概括本节判断及其与全文的关系，再展开事实。

N 研究局限
仅当终止原因或未解决缺口表明确有实质局限时生成；不得把普通免责声明扩写成一节。

N+1 综合结论
作为正文最后一节，综合已有事实形成总体判断、关键关联和后续趋势，不引入正文没有的新事实。

参考内容
[1] URL
```

额外约束：

- 正文继续使用 `1`、`1.1`、`1.1.1` 数字层级，不使用 Markdown `#` 标题。
- 总述和结论中的事实性判断仍需引用来源。
- 主题章节之间使用自然承接句，避免连续堆砌事件或来源摘要。
- 结论必须综合多个主题，不得简单重复总述，也不得输出行动口号。
- URL 仍只出现在末尾来源区，正文只显示 `[1]` 形式的引用。
- 英文报告仍使用 `References`；本次只把中文来源区标题改为“参考内容”。

## 5 实现边界

- `multi_agent/nodes.py`：增加调用 Supervisor 前的纯确定性终止判断；现有 LangGraph 拓扑不变。
- `prompts/writer.py`：把报告结构、过渡和结论要求写成明确的 Writer 系统契约，不增加调用次数。
- `writer/renderer.py`：中文来源区标题改为“参考内容”，引用编号和首次引用顺序保持不变。
- 测试：覆盖终止边界不调用 Supervisor、仍有执行容量时继续调用、Writer 必需结构提示以及中文来源区标题。

## 6 错误处理与可观测性

确定性终止仍发出 `replanning.completed`，并携带原有的 `termination_reason`。由于没有发生 Provider 调用，不再产生误导性的 `supervisor.retry` 或 `supervisor.fallback`。可行动阶段的格式错误事件保持不变，便于区分真实模型结构问题和正常硬边界结束。

时间和 Token 继续只作统计。该改动预计减少硬边界处的一至两次 Supervisor 调用，但在同模型、同问题的真实对照测试完成前，不宣称固定百分比收益。

## 7 验收标准

1. 复现 r5 部分完成且 Supervisor 轮次耗尽的状态时，Supervisor 调用次数为零，最终缺口来自 r5，终止原因为 `supervisor_round_limit`。
2. 存在叶子缺口且仍有完整执行容量时，仍调用 Supervisor 并允许生成补查任务。
3. Writer 提示明确要求“1 总述”、主题承接、必要时的“研究局限”和正文最后的“综合结论”。
4. 中文报告来源标题为“参考内容”，正文仍无 URL；英文标题保持 `References`。
5. Writer 仍只调用一次正常生成流程，没有新增 Critic/Editor 调用。
6. 全量测试、相关 Ruff、编译和本地前端检查通过。
