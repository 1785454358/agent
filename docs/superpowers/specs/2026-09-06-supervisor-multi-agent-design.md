# Supervisor Multi-Agent 独立研究模式设计

日期：2026-09-06

状态：用户已于 2026-09-06 确认；尚未实现新模式。

## 1. 用户已确定的范围

新增第三种研究策略，不用新策略替换现有 Deep。

| API / CLI mode | 前端名称 | 策略 |
| --- | --- | --- |
| `basic` | Basic · 快速研究 | 保持当前默认工作流 |
| `deep` | Deep · 自主深度研究 | 保持当前 Plan-and-Execute、ReAct、动态重规划 |
| `multi_agent` | Multi-Agent · 协作研究 | 新增 Supervisor、多独立 ReAct Researcher、Writer |

`multi_agent` 与显示名称是本设计的命名选择。默认模式仍为 `basic`，已有 `deep` 请求与历史记录含义不变。

禁止修改 `backend/src/deeptrace/deep/` 下的执行策略、提示词、状态与计数语义，也不改写已有 Basic 工作流。允许在公共入口追加分支、在公共统计结构追加默认零值角色，以及增加配置与前端选项；这些增量必须通过旧模式回归测试。

时间、Token、估算费用仅用于观测，不作为整次研究的停止条件。保留有限任务数、模型循环次数、工具调用上限和单次请求超时。保持数字分级标题、正文按首次出现排序的数字引用和文末 URL。

不恢复 ResearchNote、Claim、Evidence、Verifier。新模式采用任务级结果摘要用于协调，不在每次抓取后增加 LLM 压缩；Writer 仍以筛选后的原文为事实输入。Basic、Deep 的资料路径不受此选择影响。

## 2. 已核对的项目接入点

- `backend/src/deeptrace/agent/service.py`：`build_real_agent()` 根据 mode 构建实例，返回统一 `AgentResult`。
- `backend/src/deeptrace/api.py`：请求与记录当前只允许 basic/deep；统一后台运行、取消、SSE 和落盘。
- `backend/src/deeptrace/cli.py`：`--mode` 枚举与模式文案。
- `backend/src/deeptrace/static/index.html`：现有页面以 select 提交 mode；只增加选项和必要的事件显示，不重做用户前端。
- `backend/src/deeptrace/config/settings.py`：新增独立配置，不覆盖 `deep_*`。
- `backend/src/deeptrace/models/metrics.py`、`observability/token_metrics.py`：当前用量字段是 planner/executor/replanner/writer；增量支持 supervisor/researcher，不把新角色伪装成旧角色。
- 当前 Deep 的 `ResearchToolbox` 同时保存研究状态、配额回调和工具缓存，不能直接作为多个研究员的共享会话或通过反复 reset 复用。

工作区已有大量用户修改及未跟踪 Deep 文件。实施时以当前工作树为基线，不回退、移动或清理它们，不把这些变更混入新模式提交。

## 3. 方案选择与架构

已比较递归搜索树、搜索后统一反思、Supervisor–Researcher 三种方式。选择最后一种：它能复用当前底层能力，同时把任务级上下文、执行机会与整体完成判断分开。

```text
问题
  → Supervisor：研究范围、独立职责、首批任务
  → Scheduler：预留工具额度、限并发执行 Researcher
  → Researcher：本地 ReAct、主动完成或受限收尾
  → Supervisor：阅读任务结果，判断核心覆盖与补查价值
      → 足够：Writer
      → 不足且允许继续：只派发具体缺口任务，回到 Scheduler
      → 无法继续：携带真实局限进入 Writer
```

只有一个主管角色，不在 Supervisor 之外再叠加 Planner/Replanner/Critic。多个研究员使用同一套程序与模型配置，但拥有独立消息历史、任务视图、配额和结果。首版不做研究员之间直接聊天、不允许研究员继续创建子 Agent、不引入新的 Agent 框架依赖。

同批任务必须可以独立研究。需要前序结论的工作由主管在结果返回后的下一批派发，而非先建立复杂 DAG。上一批已取得的结果与原文保留，补查不清空或替换旧任务。

## 4. 状态与数据契约

以下结构是研究执行与协调状态，不是逐条事实验证实体。

### 4.1 研究委派

`ResearchAssignment` 包含：

- `id`：程序分配的稳定 ID，按创建顺序生成 `r1`、`r2` 等，模型不能改写已存在 ID。
- `objective`：要回答的子问题。
- `required_outputs`：有限的必需交付项；只量化用户明确指定的数量，或说明与问题规模匹配的代表性范围，不凭空扩张为全面穷举。
- `excluded_scope`：由其他研究员负责或本次不需要覆盖的范围。
- `source_guidance`：建议来源类型与查询方向，不预设未经检索确认的事实。
- `parent_ids`：补查所针对的既有任务，初始任务为空；只能引用当前运行中的已执行任务。

### 4.2 研究交付

`ResearcherResult` 包含 `task_id`、`status`、`summary`、`source_urls`、`gaps`、`stop_reason`。

- `completed`：必需交付已确认，且有与任务相关的已读原文支持。
- `partial`：有可用材料，但必需交付尚未完全确认。
- `blocked`：未取得支持交付的材料，或执行失败。
- `summary`：简洁任务结果，不是私有思维链；来源关联与不确定性明确。
- `gaps`：具体未解决或未确认的问题，区分影响核心回答的缺口与可选扩展。禁止仅写“部分清单项未确认”。
- `stop_reason`：独立记录主动结束、轮次上限、本地工具上限、服务失败或收尾解析失败。

`source_urls` 必须属于该研究员实际读取过的来源，包括读取的运行内缓存；不能凭其他任务全局存在来源就宣称当前任务完成。复用有效原文不要求再次联网抓取。

### 4.3 主管决策

`SupervisorDecision` 只有 `dispatch` 或 `finish` 两类动作，并携带简短可展示的判断依据。`dispatch` 提供新委派；`finish` 提供回答是否充分及具体局限。

主管不能靠一句“完成”抹掉未执行的必需方向或未解决的关键缺口。补查关联原任务，但创建补查任务不等于解决缺口；只有结合返回结果重新评估后才能更新整体判断，原始任务结果作为历史保留。

任务 `partial` 不自动触发补查；主管判断缺口是否影响用户问题、已有原文能否回答、额外搜索是否值得。用户明确要求而仍未解决的内容不得降级为“可选”来使状态变绿。

## 5. 两层循环与收尾

### 5.1 Supervisor

初次调用给出研究范围与一批独立任务。批次完成后读取任务结果，决定结束或派发定向补查。模型默认只看研究问题、委派历史、任务结果和可用来源索引；如对某一结果需要核对，由工具层按对应任务选取少量相关原文，不能每次拼接所有网页。

使用普通工具绑定与本地参数校验，不设置强制 `tool_choice`。结构无效最多修复一次；该调用照常计入模型调用次数、Token 和耗时，并产生可见重试事件。若仍无效，保留已取得资料并降级，不能绕过配置无限重试。

达到主管循环上限时禁止继续 dispatch，仍允许该次调用对已有结果作最终判断。没有下一次评估机会时，不再发起一批新研究。

### 5.2 Researcher

单研究员使用本地 ReAct 循环，工具为 `research_topic`、`search_web`、`fetch_page`、`search_memory`、`finish_research`。每次模型响应最多执行三个独立研究工具，结束工具不能与研究工具混合。无效批次不产生网络请求，并消耗当前模型决策机会。

模型正常情况下自主结束；不同任务不要求跑满固定轮次。轮次上限内预留最后一次模型调用用于收尾：如果此前未正常完成，最后一次只提供 `finish_research`，不再允许搜索。仍不强制 tool_choice，校验失败时产生保守结果并记录 `finalization_failed`。

本地或全局网络工具额度用尽时也进入预留收尾，而非直接终止整次运行。收尾必须能读到最后一轮工具结果。主动正常完成后不再增加一次摘要调用；所有模型调用均统计，不隐藏“额外一轮”。

收尾失败时不凭资料非空推断 completed：有材料则 partial、无材料则 blocked，具体必需项标为“未确认”，不能虚构逐项完成情况。

## 6. 资源隔离与首版默认值

新设置使用独立 `multi_agent_*` 字段和 `DEEPTRACE_MULTI_AGENT_*` 环境变量。

| 设置后缀 | 默认值 | 含义 |
| --- | --- | --- |
| MAX_RESEARCHERS | 6 | 整次运行创建的研究员总数，含补查 |
| MAX_BATCH_SIZE | 3 | 一次最多派发的独立任务数 |
| CONCURRENCY | 2 | 同时活跃的研究员上限，多余合法任务排队而非丢弃 |
| MAX_SUPERVISOR_ROUNDS | 3 | 初始规划、反馈调整、最终评估的最多轮数；每轮结构修复最多一次 |
| MAX_RESEARCHER_ROUNDS | 4 | 每任务模型决策总上限，含预留的一次收尾；收尾不额外重试 |
| MAX_TOOL_CALLS | 30 | 整次运行实际搜索、抓取尝试的总上限，不按研究员数倍增 |
| MAX_TOOLS_PER_RESEARCHER | 10 | 每研究员搜索、抓取尝试的硬上限 |
| CALL_TIMEOUT_SECONDS | 45 | 单次研究模型或工具请求超时，不是运行总时限 |
| MEMORY_MAX_AGE_DAYS | 7 | 新模式复用历史页面的有效期 |
| MEMORY_PATH | `memory/multi-agent-pages.jsonl` | 新模式独立历史缓存文件 |

默认值是可调工程起点，不承诺特定耗时或 Token 降幅。模型与价格设置首版复用现有配置；多模型路由不在首版范围。

工具计数使用实际网络尝试：一次搜索计 1，一次抓取计 1，失败尝试也计数；`research_topic` 外壳不另收一次，内部操作按相同规则计数。缓存命中和本地记忆查询不扣网络额度，但模型轮次和每轮工具批次数仍受限。事件分别记录逻辑工具调用与网络尝试，避免与 Deep 现有计数混淆。

首次派发前预留总网络额度的 20%（向下取整）给后续批次；其余在首批任务间等分、余数按稳定任务顺序分配，且不超过单任务上限。以默认三个任务为例，每个首批任务获得 8 次，补查保留 6 次。首批任务不能借用未执行任务或补查的预留额度。

每批完成后收回未使用的额度；下一批按相同等分原则从可用池分配，不超过全局剩余与单任务上限。额度检查、分配和消费必须原子化。若额度无法支持每个新任务至少一次搜索加一次抓取，拒绝该派发并让主管缩小批次；不能悄悄跳过待办、改变用户要求或标记已完成。

主管、研究员收尾和 Writer 不消耗网络工具额度，各自模型调用仍受上述循环/既有 Writer 重试规则约束。

## 7. 工具、原文、记忆与并发

新建运行级 `SharedResearchResources`，保存页面缓存、规范化 URL 索引、查询缓存、进行中的请求及网络额度。每研究员获得独立工具视图，保存当前任务、已读来源与本地工具使用量。不引用或改写 Deep 的可变工具实例。

底层复用现有搜索函数、`AsyncWebFetcher`、`ContextCompressor`、BGE 运行时及 `ResearchMemory` 的公开能力。复用能力不等于共享可变任务状态。

相同规范化 URL 或相同查询的并发请求采用单飞：一个请求执行，其他等待并复用。只有发起者扣网络额度，等待者记录缓存复用。不同任务对同一页面的 BGE 选择可以不同，不能把其他任务的片段当成自己筛选的结果。涉及模型线程安全的 BGE 调用通过新模式资源层串行保护。

网页内容与工具结果均为不可信数据；模型不得执行其中指令。保留底层 URL 安全校验与重定向检查；研究员只能读用户提供、搜索返回或缓存索引中的 URL。不能为减少 unknown_url 错误而放开任意模型生成地址。

运行内缓存默认启用，历史页面记忆沿用显式开关 `use_memory`，但使用独立的 `multi_agent_memory_path`，默认不与旧模式写入同一个文件，不迁移或覆盖原有记忆。历史页面必须保留抓取/发布时间，时效敏感事实允许 refresh；refresh 与缓存结果区分，失败刷新不能被伪装成新抓取成功。

只有运行所有者关闭 fetcher、持久化资料；单研究员结束不关闭共享资源。多个 API 运行彼此隔离。并行新模式运行写同一个历史文件时，需在进程内对“重新读取、合并、写入”串行保护；跨进程持久化不作为首版新增承诺。显式把新缓存路径配置为旧模式文件会引入未统一加锁的写入方，首版配置校验拒绝两个解析后路径相同，保证无需修改 Deep 的持久化行为。

## 8. Writer、错误处理与观测

Writer 复用现有 `WriterAgent` 和格式渲染。传入按研究方向分配并全局去重的相关原文，避免首个方向挤占全部输入；任务摘要只提供组织方向，不替代原文成为事实依据。传入的 URL 列表必须与实际纳入 Writer 的原文一致。

主管汇总为足够且 Writer 正常输出时才标记运行 completed；存在关键缺口、必要方向未执行或 Writer 降级则为 partial；完全没有可用研究材料则 failed 并明确说明，不能输出看似有依据的完整报告。

一个研究员模型/工具异常只影响自身结果，不取消其他独立研究员。初次规划失败且没有资料时返回失败；后续主管失败时用已有资料生成带局限的报告。用户取消必须向活跃/排队研究员传播并等待协程退出，不吞掉 CancelledError，不继续启动 Writer。同步 SDK 已发出的远程请求可能无法撤回，这一限制不应被描述为可取消远端计费。

沿用 RunEvent、SSE、AgentResult 与落盘协议。新事件包含 `supervisor.started`、`supervisor.dispatched`、`supervisor.reviewed`、`researcher.started`、`researcher.completed`、`tool.started`、`tool.completed`、`quota.reached`、`research.gaps` 和现有 writing/run 事件。details 携带 task_id、batch_id、父任务、次数、来源数与结束原因，不能仅靠自由文本还原并发轨迹。

用量新增 supervisor/researcher 角色，兼容旧记录缺失字段的默认零值；总量只累计一次，重试/收尾都计入。每研究员明细放事件或新模式附加统计中，不能再加进角色总量造成重复。Provider 未返回用量时标记统计不完整，不声称真实成本为零；不能把已包含在 output_tokens 中的 reasoning_tokens 再加一遍。

总耗时使用整次运行的墙钟时间；角色耗时为累计调用时长，并发时可能大于总耗时，UI 与文档需明确区分。run.completed 继续提供总耗时和 Token。API Key 与原始服务异常信息不得出现在事件或文档。

## 9. 预计文件边界

新增 `backend/src/deeptrace/multi_agent/`：

- `models.py`：主管决策、委派、研究交付与工具参数。
- `prompts.py`：主管、研究员、受限收尾提示。
- `runtime.py`：次数、事件与统计，独立于 Deep RunRuntime。
- `resources.py`：运行级缓存、单飞、配额租用、共享依赖生命周期。
- `tools.py`：任务视图、底层工具组合、原文/记忆检索。
- `researcher.py`：独立 ReAct 与有限收尾。
- `supervisor.py`：规划与批次反馈评估。
- `agent.py`：批次调度、取消传播、最终写作与 AgentResult 适配。
- `__init__.py`：公开新模式构造入口。

修改公共入口、配置、统计和前端的范围限定在第 2 节。新增 `backend/tests/multi_agent/`，公共测试只增量覆盖新模式，不改低旧断言来掩盖回归。此时不移动 Deep 到公共包、不提取 Basic/Deep 内部逻辑、不重写 frontend。

## 10. 实施验收

测试优先使用按任务 ID 路由的脚本模型和屏障控制的异步假工具，不用共享 FIFO 模型响应假装并发，也不用长 sleep 检查并发。

- 三个初始任务中 r1 达到本地上限，r2/r3 仍启动且获得预留额度；并发数不超过配置。
- 组合工具、多任务竞争、失败尝试、缓存命中与刷新场景都不超扣/重复扣网络额度。
- 同 URL 并发抓取一次，多研究员能够独立引用；会话不带入其他研究员的完整消息历史。
- 最后一轮资料被收尾读取；工具归零后收尾仍执行；正常提前完成不重复总结。
- 已有原文复用可完成任务，不强迫重复联网；仅搜索摘要不能伪装为已读原文。
- 有具体关键缺口时定向补查；可选扩展不会无限派发；补查创建不清空旧缺口。
- 主管与研究员轮次、结构修复、总研究员数达到上限时都有确定结束路径。
- 单任务失败不传播为全批失败；用户取消能清理活跃与排队任务，并关闭共享资源一次。
- Writer 有各方向材料、来源匹配；数字引用、数字标题及降级行为保持。
- 模型统计包含每次实际返回 usage 的调用；墙钟时间不等于并行任务耗时相加；缺失 usage 明确显示不完整。
- API、CLI、前端支持三个模式；未知模式仍拒绝；Basic 默认及 Deep 现有路由、配置、测试不变。
- 完整后端测试、静态检查、前端模式切换与事件展示验证通过后，再做有真实凭据的有限端到端对比；不预先承诺 Token 下降百分比。

对比选择相同模型、相同问题与相同全局网络额度，报告核心覆盖、引用正确性、重复查询、网络尝试、Token、墙钟耗时。保留现有 Deep 作为基线，而不是只比较 completed 标签。
