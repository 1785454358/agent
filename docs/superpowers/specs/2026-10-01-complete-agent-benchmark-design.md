# 完整 Agent 评测系统：真实数据、对照实验与证据链

日期：2026-10-01。

状态：用户已确认混合评测方案的范围；本文待用户审阅。尚未实施本方案，尚未执行本方案的真实 API 实验。

## 1. 目标与完成标准

建设可持续运行、可复现配置、可追溯结果的本地 Agent 评测系统，为 Harness 优化、简历和面试提供真实证据。成熟指数据治理、实验控制、评分校准、错误留样、资源限制和回归闭环，不指堆叠服务或保证高分。

最终必须交付：

1. 版本化真实资料题集、公开基准子集清单和记忆场景集。
2. 简单研究基线与 Harness 的同条件对照，以及独立的记忆 on/off 实验。
3. 真实模型输出、取回证据、执行轨迹、资源统计和适用的 Ragas 评分。
4. 可复核的逐题结果、分类对比、不确定性分析、失败分析与人工复核记录。
5. 可续跑的命令行工作流、离线回归测试和 CI 配置。
6. 引用真实实验身份和数字的简历表述、面试说明与复现实验指南。

只完成 SDK 联调、离线单元测试或单题 smoke 不满足完成标准。没有提升也是有效实验结果，不筛选成功题伪造收益。

## 2. 现有基础与设计取舍

沿用 `backend/src/deeptrace/eval/` 的数据加载、冻结资料环境、真实 Harness runner、故障注入和报告基础，以及 `backend/evaluation/` 的独立 Ragas 环境。生产 OpenAI SDK 不降级，独立评测环境不安装整个生产项目。

已完成的工具切片见 [独立 Ragas 工具评测说明](../../evaluation/isolated-ragas-tools.md)。它使用脚本模型与合成短文验证工具指标，并非真实质量基准。现有三题 smoke 和 `corpus.example` 资料继续保留作为离线契约测试，不计入本方案的真实数据规模。

本文件替代 [早期评测设计](2026-10-01-agent-evaluation-design.md) 中尚未实施的题集规模、质量评分与实验预算建议；不改写已完成切片的历史记录。

方案比较：

- 推荐混合方案：真实官方资料的受控题集负责定位机制收益，公开研究任务子集负责外部验证，记忆专项负责验证状态与召回。
- 仅自建题：定位问题容易，但任务选择偏差较大、外部参照不足。
- 仅公共基准：参考标准明确，但网络变化、模型评审成本和任务适配性不利于独立解释 Harness 与记忆的收益。

不建设评测微服务、账号体系、云看板、分布式调度或新的 Agent runtime。首版主实验比较 baseline 与 Workflow，不将三种研究策略的全矩阵变为必要条件。

## 3. 数据集：真实、可追溯、与被测系统隔离

### 3.1 真实资料研究题集：30 题

采用六类各五题：单跳事实、多跳综合、方案对比、版本/时效边界、冲突资料、证据不足。任务以 Agent 与大模型应用工程为主，覆盖持久化与恢复、工具治理、检索与记忆等主题，但参考事实来自外部官方资料，不来自项目自述。

每类固定两题开发、三题留出测试，共 12 道开发题和 18 道测试题。先依据主题和来源分组划分，再冻结任务 ID 清单；同一问题的改写不能跨集。优化只能使用开发集；读过测试结果后再优化，需要记录测试集已暴露并另建版本，不能继续声称未见测试集。

每题记录：题目 ID、分类、split、任务输入、参考事实、参考回答、成功要求、允许不确定/拒答的条件、资料来源定位、资料版本及审阅状态。评分用的参考事实/答案字段及答案定位标注不出现在模型输入、检索索引、工具输出、记忆或 checkpoint 中；原始公开资料中的事实本身当然允许被检索。

每份资料记录：原始 URL、发布方、标题、获取时间、版本/提交身份、内容哈希、许可或使用条件、用于核验的段落定位。冻结公开资料为研究时点的事实；报告不能把快照结论自动描述为当前最新事实。

只将许可允许再分发的内容纳入可公开语料；其他来源保留链接、获取配方和哈希，快照本地使用且不默认提交。许可无法核实的来源替换，不默认为可以复制。获取失败或无法定位参考事实的题不得用编造正文补齐。

模型可以起草问题和参考回答，但需逐事实核验来源。审阅字段区分 `source_verified` 与 `human_reviewed`，记录审阅人、时间和修订；代理核验不冒称独立人工金标。30 题全部要求来源核验；未人工审阅的数量和比例在报告中明确显示。

### 3.2 公开基准子集：5 题，独立报告

选用 DeepResearch Bench 官方任务中五道适配工程研究的任务。导入时固定上游 commit、任务 ID、许可、原始任务内容及选题规则；在看到本项目输出前冻结选择。排除需要私人数据、不可用专用工具或专业医疗/法律/投资判断的任务，排除原因随清单保存。

资料冻结题集与公共基准不混合。公共任务使用真实搜索/抓取，保存实际访问资料快照与时间；网络波动是实验条件的一部分。

首版运行公开任务，并以本系统声明的评分配置进行外部子集验证，标识为 `DRB-subset-local-evaluation`。使用自选模型或不同规则的评分不能叫官方 RACE/FACT 分数，不能与官方榜单作直接数值比较。官方提交、完整官方评分流水线和额外 Jina 服务不在首版必需范围。

若上游参考答案/评价材料不能合规取得，保留任务执行与可适用的证据评分，参考依赖指标标为未测，说明覆盖率；不能用被测回答反向生成参考答案。公开子集单独形成探索性报告，不据五题外推总体能力。

任务来源与官方方法：[DeepResearch Bench](https://github.com/Ayanami0730/deep_research_bench)。官方包含报告评价 RACE 与引用评价 FACT；本方案借鉴维度但不将自定义适配冒充官方复现。

### 3.3 记忆场景：12 个 episode

六类各两个 episode：偏好延续、同用户跨会话召回、研究背景复用、过期信息、同身份更新/遗忘、用户/工作区隔离。缺失与存储/索引不可用的退化行为另设故障回归。

每个 episode 由写入/研究前置轮、后续任务、时钟变化和断言组成。场景中的用户是测试身份，不是真实用户日志；报告明确“受控多轮场景＋真实模型调用”，不冒称线上用户数据。

on/off 接收相同前置用户输入与后续请求，off 跳过长期写入/召回，双方保持相同短期线程规则。跨会话题的新线程不获得旧对话全文。原始用户内容可保存，但参考答案、预期 recall ID 和评分断言不提供给 Agent。

每个 episode 使用独立本地临时 SQLite、namespace 和证据存储，组间清空，组内允许连续；与生产数据库、用户历史记忆隔离。固定时钟用于 TTL，不用等待现实时间推进。

主实验以确定性检索配置验证生命周期与端到端效果，并标识后端。只有在实际启用 Chroma 与真实 embedding、记录模型身份并执行专项后，才能报告语义记忆结果；lexical 或 mock 结果不得推广为向量召回能力。

记忆必须通过既有写入、生命周期和召回边界，不能只直接种子 Store 后把结果称为生产写入端到端。低层种子适用于故障边界测试，须单独标注。

## 4. 架构与数据契约

采用单一实验清单和版本化文件契约：数据校验 → 执行矩阵 → 原始记录 → 独立评分 → 对照报告/复核 → 回归。

职责边界：

| 部分 | 负责 | 不负责 |
| --- | --- | --- |
| 数据与 manifest | 校验资产、划分、配置、选题和实验身份 | 向 Agent 泄露参考答案 |
| 生产环境 runner | 调用真实 Harness/基线，存证据、状态、轨迹和 usage | 装 Ragas、决定最终评分 |
| 独立环境 scorer | 读取版本化记录、调用 Ragas、缓存逐项评分 | 重跑研究或修改运行终态 |
| 分析与报告 | 配对比较、覆盖率、误差、复核材料、回归差异 | 静默过滤失败、制造总分 |

在现有模块上扩展，不预先规定大量空模块。保持 schema 与 framework adapter 分离；共享契约不依赖生产冲突包。新的完整记录使用独立 schema 版本，旧 `tool_eval.json` v1 保持可读，不无版本地替换结构。

manifest 必须包括数据/语料/选题清单哈希、源码身份、依赖锁身份、研究与 judge 模型、去密钥 provider 标识、生成参数、工具后端、预算、检索/记忆配置、随机种子、评分/提示版本和起始时间。密钥与认证 header 不写入任何记录。

不能只记录 Git HEAD：未提交且未跟踪的 eval 代码也影响实验。保存相关源码文件哈希清单；dirty 实验标注为工作区快照，不称凭 commit 即可复现。公开复现材料需包含适用的源码/依赖/数据配方。

每次运行保存完整答案、权威应用 status/reason/gaps、证据正文或可解析的内容寻址引用、模型请求与工具结果、资源 usage、时间及错误类别。终态继续来自 ApplicationRunResult，不重新猜测 completed。旧的 4000 字符答案节选不能作为完整质量评分输入。

轨迹必须保留模型可见消息和已完成的工具响应，包含最终没有送入下一次模型的结果；分支与序号明确，不按并发结束顺序伪造单一因果链。无法可靠关联的 ID 显式保留未知，不编造关联。

完整输出和资料按文件保存，不全部膨胀到 LangGraph state。评审输入可按显式 token 上限裁剪，但记录裁剪方法与遗漏内容；不能把局部评分称为全文评分。跨分支任务目标优先以最终回答与可核验目标评价；消息无法满足框架要求时相应指标未测，不伪造对话。

## 5. 对照实验与公平性

### 5.1 简单研究基线

实现真实的 search → fetch → answer：使用任务原文搜索，按返回排序抓取最多三个允许访问的来源，再使用统一报告要求生成带引用回答。无动态规划、无研究自评循环、无长期记忆；不能读取任何 gold。

基线与 Workflow 使用相同研究模型、temperature、输出要求、资料/搜索适配器、ToolGateway 治理和资源上限。主对照双方长期记忆均关闭；记忆收益由独立 on/off 实验回答。

相同上限不要求基线消耗相同调用数：保留实际消耗，展示质量与成本/延迟的权衡。随机或交替运行配对顺序，避免持续网络变化只影响某一系统。

冻结资料的检索后端与真实互联网搜索不是同一个环境，结果必须分开。资料语料相同，参数相同，不能给 Harness 更丰富的文档或手工命中提示。

### 5.2 实验规模与身份

目标矩阵：研究集 30 题 × 两系统 × 两次重复 = 120 次运行；记忆集 12 episode × on/off × 两次重复 = 48 个 episode；公开子集 5 题 × 两系统 × 一次 = 10 次探索性运行。

这些是完整实验的目标规模，不是已授权消耗额度或已经取得的数据。开发集与测试集分别报告。公开网络的重复性和模型非确定性通过时间、配置与资料留样解释，不能承诺每次输出逐字一致。

研究对比比较整个 Harness 与简单流水线，只能说明整体方案差异，不能声称单独证明了某一个内部机制的因果贡献。记忆对照只改变长期记忆开关，其他配置固定。

新增可靠性故障集与自然研究题分开，覆盖超时、临时失败、上下文/调用预算、重复工具执行、无资料、取消和 checkpoint 恢复。离线注入结果标为工程可靠性，不混入自然真实任务成功率。

## 6. 指标、适用性与校准

采用 Ragas 作为通用质量与工具评分框架，pytest 验证确定性工程契约。固定已验证的独立环境版本；新增指标需要验证安装、接口和实际评分，不因包能导入就宣布接入成功。

| 维度 | 指标/判断 | 解释边界 |
| --- | --- | --- |
| 工程终态 | completed/partial/failed、gap、恢复与预算断言 | completed 不等于答对 |
| 目标达成 | Ragas AgentGoalAccuracy 的参考目标形式 | 需完整且有效的评价输入 |
| 事实 | Ragas FactualCorrectness F1 | 对照参考事实，不等于引用支持 |
| 证据忠实 | Ragas Faithfulness | 结论能否由取回上下文支撑，不代表引用指向正确 |
| 工具 | 已接入的 ToolCallAccuracy/F1、执行错误和冗余计数 | 仅适合有明确参考调用的受控任务 |
| 引用 | 引用合法率、逐声明-来源支持核验 | 语义支持规则单独标为本地引用评价，不冒称 Ragas 官方指标 |
| 记忆 | 目标满足率、有效记忆召回、失效命中、隔离违例、资源变化 | 控制场景和后端，不能冒称线上效果 |
| 效率 | input/output token、模型/工具请求、p50/p95 延迟、费用 | 无 provider usage/价表为未知，不猜测 |

开放研究允许不同合法工具路径和搜索改写，不给它强行标注唯一工具序列。工具指标继续承担受控契约验证；参考不存在标为未适用，不能用 Agent 自身轨迹生成 gold 后获得满分。

逐声明引用评价记录事实声明、引用 URL、对应证据定位、支持/反驳/无法判断；在允许的评审限额内核验。没有穷尽检查全部声明时，只报告抽样数量与抽样方法，不能称完整引用准确率。

逐指标记录 `ok / not_applicable / error`、值、依据、judge 身份、prompt 版本与评审费用。未测或失败为 null。Agent 失败留在所有任务的完成率分母中；质量均值同时显示覆盖率，并提供双方均有效评分的配对结果与未配对数量，不让幸存样本均值掩盖失败。

judge 独立配置，不隐式沿用研究模型。配置相同则明确标记 same_model，解释自评偏差；没有可用配置就不编造分数。相同回答评分失败只重试评分，不重新运行 Agent 寻找更好回答。

人工校准包至少覆盖 10 道题的 baseline/Harness 配对回答，并额外包含冲突、证据不足与错误案例。审阅时隐藏系统标签、打乱顺序，记录判断、依据、与 judge 的分歧和修订。未获得人工回复时交付待复核包，报告校准尚未完成；不能由代理填一个“人工一致率”。

参照官方说明：[Agent metrics](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/agents/)、[FactualCorrectness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/factual_correctness/)、[Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)。实施以锁定版本的真实 API 为准，不把 latest 文档中的新名称直接当作 0.4.3 已支持。

## 7. 预算、安全与失败处理

默认仍离线，真实运行必须显式选择并经过 preflight。preflight 校验数据身份、完整实验矩阵、研究/judge 配置、是否允许联网、独立资源上限和输出位置；未配置批次上限不得开始真实调用。

校准建议使用开发集三题 × 两系统，以及两个记忆 episode × on/off：共六次研究运行与四个 episode。记忆 episode 内的多轮共享 episode 预算，不按每轮无限重置。这是建议的下一次真实运行规模，本文写入不启动该实验。

研究校准起始候选沿用已经通过的真实 smoke 量级：每研究分支最多 12 轮、每运行最多 40 次逻辑模型请求、24 次工具请求、每模型调用最多 2048 输出 token、240 秒。对多轮 episode 的时间上限单独声明为 480 秒，逻辑调用/工具共享上限仍为 40/24。实际配置进入 manifest，不静默沿用 eval runner 的旧八轮默认值。

每逻辑模型请求最多两次 transport attempt，因此研究批次还必须具备 provider 请求 attempt 的硬上限；启动前在并发边界预留额度，不靠结果回收后才发现超额。judge 单独限额，校准每份可评分记录最多 12 次 provider attempt、每次最多 2048 输出 token、180 秒。一次 Ragas 指标可能包含多次模型调用，计数包住实际请求，超额显式中止该指标并保留已成功项。

token 输入限额按模型上下文配置显式声明；provider usage 缺失不能用估算冒充实际值。费用按带日期、币种、输入/输出与缓存价规则的价表计算并标为估算；账单金额仅在有真实账单时报告。没有可靠价格配置时不承诺人民币/美元硬上限，使用可强制的请求数、token 请求上限和时间边界控制。

完整矩阵开始前根据校准数据展示预计资源范围，另行确认总调用/费用边界。先执行校准不自动授权 178 个目标运行/episode 或无限调参。预算不足时报告完成范围与停止原因，而不是删除失败重新跑直到过关。

数据外发仅包含公开研究资料和测试身份的场景输入；不上传源码、密钥、生产用户历史或真实私有记忆。默认关闭 Ragas 遥测与云追踪。资料、工具返回和被评分答案均是不可信数据，不可覆盖评分规则或工具安全策略。

系统异常逐项留样、矩阵继续安全项；配置/数据契约错误在调用前停止。用户取消传播并停止后续付费请求，已完成输出保存。日志导出使用错误类别和脱敏信息，不原样写 provider 凭据或错误响应。

## 8. 可续跑、缓存与统计报告

每次运行结束即写独立记录，采用临时文件加原子替换，不能等整批结束才落盘。记录缺少、未完成写入、已完成失败三种状态区分；默认续跑只补未执行项，重试失败必须显式生成新 attempt 并保留旧记录。

评分缓存键包含输入记录、证据内容、参考目标、模型/生成参数、framework、prompt/adapter 版本。缓存命中不计新请求，同时显示原评分身份；变更任何评分相关内容均失效。缓存不得跨身份复用结论。

报告至少包含逐题/逐 episode 输出、数据来源与审阅状态、配置、所有失败、指标适用/错误/未测数量、开发/测试/公开子集分栏、配对差值、分类均值、资源与延迟分位数、记忆违例和样例分析。

重复先在题内聚合，采用按题配对的 bootstrap 95% 区间和固定随机种子；不能把同一道题的重复当独立新题增加样本量。记忆按 episode 聚合。无有效配对时均值与区间为 null，只有一个配对时展示差值而不计算区间。小样本和五题公开子集标为探索性，区间不能证明外部总体效果。

不设随意加权总分，不用未经校准的 0.8 作为行业通过线。CI 默认运行无网络契约/工程回归；真实质量实验显式触发并有预算。硬安全/隔离违例为阻断项；统计质量阈值只能在校准后用开发数据设定并版本化，不能看测试成绩倒推阈值。

产物：manifest、数据卡、原始运行记录与内容哈希清单、score records、comparison report、review pack/review results、failure analysis，以及使用说明和简历/面试材料。JSON 保存完整可机读结果，Markdown 负责阅读；不要求额外商业看板。

## 9. 验收与实施顺序

本方案是一条共享文件契约的评测工作流，按连续可验收切片实现，不拆成相互独立的新平台：

1. 实验契约、全量答案/证据/usage、限额、落盘续跑与脱敏。离线测试验证缺失/失败、不重复调用与取消；现有工具导出保持兼容。
2. 基线、真实资料数据治理和开发/测试切分。用相同题目跑双方，验证参考字段不进入模型/工具/记忆输入。
3. 独立 Ragas 质量评分、引用复核、缓存、配对统计。先真实框架的离线可控案例，再有限真实 judge；禁止用 stub 分数证明实际框架接入。
4. 记忆多轮 runner 与生产边界、故障可靠性回归、公开任务子集导入。明确后端、网络和许可，保留未适用指标。
5. 预算确认后的真实校准与完整矩阵、人工复核、报告、复现指南和简历面试材料。

每个切片做 TDD 和代码质量审查；全量离线回归不能退化。真实实验需检查记录与 checkpoint 一致、预算可控、实际评分有依据，再扩容。提升数值只来自完成且冻结的报告，明确题数、重复、模型和对照配置。

最终检查不得只说测试通过：必须说明真实研究运行数、真实 judge 请求数、使用资料/题目数量、人工复核数量、评分覆盖率、自然任务失败率、公开子集范围、实际与未知资源，以及尚不能支持的结论。

如果预算、judge 配置、人工复核或上游许可限制实验，工程交付与数据验收分别列状态，不把未完成的真实验证写成已完成。人工金标/校准未完成时不得生成宣称人工验证的简历句子。

## 10. 设计自审与待审阅边界

- 数据数量、切分、公开子集和多轮实验分母已明确；合成契约题不冒称真实资料。
- 保留已有代码和生产依赖；只扩展评测相关边界，不做无关 runtime 重构。
- 区分工程完成、任务答对、证据忠实、引用支持与记忆收益；不输出混淆性的总成功率。
- 全量目标规模不是消耗授权，真实校准与完整矩阵均需显式限额；本次只写设计文档。
- 真实数据不等于真实用户日志；来源核验不等于独立人工审阅；公开子集本地评分不等于官方榜单。
- 实验不预设提升，原始失败、评分错误、未知 usage 与未复核样本全部可见。

用户审阅本文后进入 writing-plans，生成具体实现计划；预算选择与人工复核安排在实际实验前确认，不阻挡离线代码与数据契约的开发。
