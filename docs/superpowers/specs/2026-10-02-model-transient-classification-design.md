# 模型暂态异常分类兼容修复

## 已确认目标与证据

用户批准最小异常分类修复，保留现有最多 2 次尝试和调用计量，不扩大权限或预算。真实开发轨迹中，新版 LangChain 把 SDK 的连接异常包装为 `OpenAIConnectionError`；现有网关按异常名称识别 `APIConnectionError`，导致包装后的连接异常被归为 fatal。

本地已安装的 `langchain_openai.chat_models.base` 同时定义 `OpenAITimeoutError`。两个类型由 SDK 连接/超时异常派生，并由相应转换分支抛出。

## 方案与范围

推荐沿用网关已有名称白名单，只加入 `OpenAIConnectionError`、`OpenAITimeoutError` 两个明确类型名称。改动仅在 `backend/src/deeptrace/harness/model_gateway.py` 的 `_transient` 中；不引入新依赖，不重构传输层。

另一方案是按 SDK 或 LangChain 异常基类做类型判断，扩展性更好，但会增加网关对 SDK 异常模块的耦合，本次不采用。捕获所有 APIError 会错误重试认证、参数和上下文错误，不采用。

数据流保持：调用失败 → 暂态分类 → 现有有界退避 → 成功返回或 `ModelCallError(TRANSIENT)`。认证、无效请求、预算哨兵维持不可重试；取消直接传播。现有 SDK 重试设置、网关尝试次数、计量、超时、退避和错误对外脱敏接口均不变。

## 验收

使用已安装的真实包装异常类做离线回归：连接/超时首次失败后第二次成功；持续失败最多尝试 2 次且类别为 TRANSIENT；401/400、取消、预算哨兵不被新增规则重试。补充计量回归，证明重试占用 Provider 尝试额度而不是免费重试。

先运行新测试确认旧代码失败，再作最小修改，运行网关、计量及非真实 API 回归并检查修改范围。测试不连接外部 API。现有真实实验运行时不更改生产或评分代码；旧实验结果不得重新标成修复后结果。

## 不在本次范围

不增加整体/分支预算，不做回答额度预留，不修改评估 JSON 大小或 planner requirement 契约，不改变证据/引用门禁，不宣称此次修复解决全部端到端失败。真实实验结果及这些问题另记在开发校准报告中。

## 规格自检与提交

已自检：范围单一、无待定项；次数为最多 2 次尝试（不是额外重试 2 次）；不修改运行中的实验身份。规格的单文件 Git 提交延后到正在执行的实验结束，以保持实验期间 HEAD 不变，不混入工作区其他修改。
