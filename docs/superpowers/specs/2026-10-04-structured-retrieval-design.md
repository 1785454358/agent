# 结构保真的正文提取与选段替换

## 状态与目标

2026-10-04 用户已同意本规格并批准实施。共享提取、选段与预览已实施；完整离线 1187 passed、独立评分环境 34 passed，一次性三模式真实研究及评分已完成。主模式F1=0.86，但partial、来源与效率验收失败；评估侧重复选段仍挤掉已读关键证据，需另行替换。结果见 `docs/evaluation/structured-retrieval-validation-20261004.md`，不宣称整体质量不降或效率达标，不扩大付费实验。

目标是修复“正文存在、引用坐标合法，但选材不切题”的取材缺陷，恢复真实联网回答质量，再评价耗时、token 和搜索 API 尝试。保持三模式及现有 Harness，不新增 Agent、向量服务、模型调用、依赖或评分规则。

根因证据见 `docs/evaluation/retrieval-root-cause-20261004.md`：最长文本策略选择了丢失段落边界的 BS4 正文；通用词累加排序让普通 Task 段落压过问题指定 API；默认 query 和仅改 Markdown 已单独回放，均不足以修复。

## 范围

本规格只替换共享取材链路：HTML 提取、原文选段、阅读预览适配及必要的默认阅读指引。三模式使用同一实现，不增加第二套特殊评测路径。

抓取与阅读合并、版本来源约束执行、Goal 判分审计、规划/Writer 重构、长页面存储上限调整均不在本轮范围。旧版本错误仍须报告，不会因本轮未实现版本门禁而从验收中删除。

## 正文提取

- HTTP 路径使用已有 Trafilatura 2.2.0 的 Markdown 输出，保留可提取的段落、标题、行内代码和列表；元数据、真实 final_url 身份、抓取时间沿用现有规则。
- 达到现有字符/token 最低门槛的主提取结果优先使用，不再无条件让更长的 BS4 文本覆盖它。主提取不可用时才降级到结构保真的 BS4；HTTP 两种提取都不可用时沿用 Playwright 降级。
- BS4 降级仍去除现有非正文元素、使用 article/main/body 根节点。按块级标题、段落、列表项、代码块和表格行形成文本；行内代码/链接与所属句子保持在一起。不得再对每个行内文本节点插入换行，也不得把所有段落空行删掉。代码块内部换行保留，嵌套块不重复提取。
- 不增加网络重试、浏览器启动或额外抓取。不对某个域名、题目或金答案设置专用抽取器。
- 20,000 字符存储上限、响应字节上限和 URL/重定向/DNS 安全检查不变。截断、提取遗漏不能冒充完整网页覆盖。
- 新提取内容按现有入库机制生成新 hash/version；已保存正文、旧支持坐标、旧 checkpoint 不原地重写。

## 按问题选段

保留现有 `select_evidence_passages` / `select_source_excerpt` 接口和固定需求输入，替换其中的排序与分配规则，不另加检索系统。

短正文能整体放入预算时，保留既有全文交付行为，不进行有损选段；工具明确标记 full，found 为 null，不宣称关键词命中或需求覆盖。以下无命中/预算省略规则适用于确实需要检索选段的长正文。此边界在实施回归中澄清，已向用户说明并提供调整选项；语义评估、引用及完成门禁不变。

1. 以抽取正文中的完整段落/列表项为基本单位；标题与后续段落关联，超长单位按完整句子分组。代码块保留内部结构；不可分割的超长单位明确省略，而不是把截断语义包装成完整段落。
2. 从实际查询识别代码标识符（反引号、限定名、下划线名和 CamelCase），进行完整 token 匹配。限定名可以同时匹配其末段标识符，其共用模块前缀不单独充当主要目标；不将 `Task` 当作 `TaskGroup` 命中，不把 Python 版本数字当成主要技术实体。普通自然语言查询沿用通用词检索，不要求有代码标识符。
3. 有目标标识符命中时，优先分配含目标标识符的段落及其标题所属内容，再使用普通词相关度排序；不能让大量通用词或较长段落压过目标实体。只有问题提供的实体参与优先级，不硬编码 asyncio、ExceptionGroup 或任何金答案要点。
4. 多个实体和已有 focus_queries 按轮转方式分配完整组，避免一个目标消耗全部预算。相同段落去重，选段最终按原文顺序展示。共用一个预算，不能给每个要点额外扩大上限。
5. 在剩余预算内补入同一结构段相邻的完整条件/例外段。这里只保证结构邻接与原文完整，不把邻接或关键词命中当作语义覆盖证明。
6. 通用查询没有可用命中时，返回明确的无匹配诊断及空片段，不默默回退正文前缀。已匹配但完整组无法适配预算时，返回明确的预算省略诊断。显式范围读取仍可供用户/兼容调用使用；诊断提示可以建议局部补读，但不自动搜索或调用模型。

默认 read 沿用本分支实际 query；全局评估使用已有固定需求 focus_queries，不新增由模型可任意扩展的权限或目标元数据。缺少结构的旧正文仍通过已有句子/行边界尽力分组，不能认为旧正文已获得新提取器的结构。

## 阅读交付和错误处理

- 预览适配先按完整阅读组分配，计入 JSON 转义、来源元数据、短引用编号等开销。默认原文读预算 2,000 字符、可申请上限 3,000 字符、工具预览 4,000 字符不变。
- 默认问题选段不再用字符二分截断最后一组去填满 JSON。完整组放不下就省略并诊断；显式范围/find 仍是有界窗口，不能宣称其语义完整。
- find/start/after 参数兼容保留，但提示不再要求优先猜测原文做 find。精确查找用于已经看到的原文术语或字符串；未命中给出明确反馈，不自动重试相同调用。
- 空片段与被省略的内容不能产生已读 anchor；实际展示的非空片段继续校验当前授权、ACTIVE 状态、tenant、version、hash 和原文坐标。预览适配及后续短引用编号均须保留完整组选段边界，不能在第二次适配时重新截断。检索信息只能说明取材情况，不能自动完成 todo、覆盖需求或放宽 finish 门禁。
- 搜索摘要仍只能发现来源；fetch 成功仍不等于已读。本规格不合并 fetch/read 响应。
- 现有评估器继续负责语义覆盖，Writer 仍只能使用已接受的支持。确定性取材不能保证任意网页 100% 切题，本轮不以关键词命中替代答案质量验收。

## 回归与验收

先写失败回归，再逐步替换并分别验证提取、排序、预览三个边界；保留现有安全、预算、引用、恢复和协议断言。不以删掉失败断言获得通过，只更新本规格明确废止的“最长即最好”和查询前缀回退行为断言。

- 提取：较长但碎裂的 BS4 不覆盖可用主提取；主提取失效时正确降级；行内 API 不被拆开；段落/否定/列表/代码结构保留；短文章不因缺标题被拒绝。
- 排序：重放实际 TaskGroup/gather 分支而不注入金答案；通用 Task 段落不挤掉目标 API；再用无关技术主题、中文文章、英文文章、多实体、无命中、旧正文和长条件段测试，防止只修诊断题。
- 预览：转义较多时仍完整分配组、明确省略；原文身份/坐标正确；无命中不记已读；保留显式窗口兼容性和未完成待办。
- 三模式：共享取材、父任务授权、缓存/重放、checkpoint、中断恢复均走相同处理；完整离线回归之后才进行真实联网复测。

真实验证另封存新前缀、源码/数据/配置身份和一次性评分登记，不覆盖或重评分旧结果。同一诊断题三模式各一次，主要看 Plan-and-Execute；保持 doubao-seed-2.0-lite、temperature=0、输出 4096、Answer 2,000 字符、记忆关闭、每分支 12 轮。

硬上限继续为每运行 40 logical / 80 Provider / 24 Gateway / 360 秒，研究批次 120 logical / 240 Provider，评分批次 48 Provider。研究与评分分别计量，评分环境及 Ragas 0.4.3 口径不变，不择优重跑或只统计 completed 样本。

主模式恢复门槛为 F1 至少 0.80，同时 completed、指定版本来源与关键行为合格；Faithfulness、Goal、所有 partial/failed/评分错误照实报告。任一门槛未过不启动扩大付费配对。通过后才比较时间、输入/输出/总 token 与搜索 API 尝试；改善取材或离线通过不能单独宣布质量不降、省时成功。
