# 证据优先的研究链路简化

起草：2026-10-03；自审及实施：2026-10-04。用户已书面确认，共享链路已实施并完成首轮真实联网复测；主模式恢复门槛未过，扩大配对未启动。详见 `docs/evaluation/evidence-first-validation-20261004.md`。

## 目标与依据

先守住同一评分口径的质量，再降低耗时、token，尤其是搜索供应商请求。不以少回答、错误版本来源、提前失败或评分规则变化换取节省。

上一轮主模式F1从0.80降到0.44，答案把gather“不取消其他任务”写反，并漏掉TaskGroup异常聚合。实际候选引用停在`If return_exceptions`，评估器照搬候选并判定覆盖；完整抓取正文包含正确的后续条件。不同版本/语言页面共用canonical URL，又使并行来源互相supersede。这些链路有实际轨迹和无API重放支持；单题单次不能证明全部退步由压缩引起。

参考已检查的实现：

- [Open Deep Research提示与压缩](https://github.com/langchain-ai/open_deep_research/blob/main/src/open_deep_research/prompts.py)：删除无关/重复内容，保留相关事实、限定条件和出处；不是复制其全部Supervisor结构或退出逻辑。
- [GPT Researcher检索协调](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/skills/researcher.py)与[相关原文选择](https://github.com/assafelovic/gpt-researcher/blob/master/gpt_researcher/context/compression.py)：URL去重、复用资料、带来源传递相关内容。不引入其embedding依赖或额外模型调用。

选择局部替换：恢复全量历史会保留重复token；全项目换框架迁移范围过大。保留三种调度方式，只修改其共享证据处理链路。

## 1. 来源身份：实际页面URL，不用发布者canonical合并版本

抓取证据的来源键采用已通过现有安全边界的`final_url`，缺失时采用`requested_url`。发布者`canonical_url`仅保留在metadata；保留实际版本/语言路径，不擅自改写、猜测URL或放宽重定向/SSRF检查。

现有EvidenceDraft/Evidence中的`canonical_url`字段继续承载仓库来源键，避免本轮数据库字段迁移；它不再等同于HTML声明的canonical。展示与引用使用实际来源键，并把标题及requested/final/publisher canonical信息交给评估视图，便于核对用户指定版本。

不同版本/语言的实际URL互不作废；同一实际URL内容更新仍执行现有版本替换。重复同URL同正文仍幂等。内存与持久化仓库语义一致，不放开读取SUPERSEDED来源、不自动复活旧正文。不改写既有证据或旧checkpoint；需要正确来源时重新检索/抓取并留新记录。

## 2. 原文视图：压缩重复历史，不压掉决定结论的上下文

修改既有选段/模型视图实现，不新增摘要Agent、向量库或另一套证据服务。研究与评估都按问题及固定需求选择相关原文句群，合并重叠范围，保留条件、否定及例外；不以任意500字符或单个换行认定语义完整。代码/内联节点的多行文本不能被当成很多独立段落。

原文阅读单元与出处单元分开：模型看到完整相关原文及来源；现有短引用仍由宿主绑定实际坐标。EvidenceSupport最多500字符、Finding最多3条supports的DTO保持，不把短quote本身当成完整阅读上下文。条件分布在多段时引用多条；复杂结论拆为独立事实，而不是扩大DTO后假装已有证明。

选段在现有硬输入预算和工具preview上限内整组保留；引用编号只对应实际显示的原文。装不下时减少其他重复/无关内容，必要时返回明确省略及续读定位，不能无标记截断后宣称充分。工具预览JSON配对、原文位置/hash、授权及未返回引用不可用的边界保持。

研究上下文继续保留原始任务、用户约束、分支需求、来源身份和最新完整工具交换；用去重的相关已读原文保留工作进度，不仅留下候选claim或失去条件的短片段。8k仍是软目标，不是牺牲关键原文的硬线；最近3组只是近期对话窗口，不是全部证据记忆。必要原文可在软目标外保留，实际输入及超限诊断如实记录，现有硬预算不变。持久历史和checkpoint不裁剪。

## 3. 研究只找资料，现有评估直接抽取事实和缺口

共享研究循环的默认路径不再强制“record_findings后才能finish”。完成请求以本分支至少一个成功实际读取、当前合法授权且ACTIVE/version/hash/坐标有效的read anchor为宿主前提；来源仅抓取未阅读、空结果或失效anchor不能通过。summary仅是导航，不是事实证据或全局完成证明。

record_findings/write_todos原有数据、工具处理及旧checkpoint解码保留兼容，但不作为默认研究路径的必经步骤。已有未完成todo仍不能被自动清空/标完成；普通小分支不强制建立todo。finish仍唯一且最后、前置失败/取消/致命错误优先、不可引用同批未返回阅读；保持既有工具批次收尾限制，不另外扩展同批网络完成协议。

现有全局评估调用直接对照完整相关原文抽取findings，并逐项判断固定需求coverage。新的模型视图不输入研究员候选claim/confidence，也不因其候选supports优先保留无关片段；旧候选留档，不作为accepted finding。上一轮已接受且仍有效的findings可以保留支持上下文，但在补查后需和新增原文一起判断冲突与完整性。

评估仍输出原有schema及本次可见p引用；宿主归一化原文supports并校验coverage关联。来源版本/用户约束不符、关键条件缺失、证据不足或冲突时保留缺口并走现有定向补查，不接受模型仅自称“已核验”。不增加独立核验Agent/模型调用，不宣称确定性坐标校验可以证明语义正确。

Writer沿用accepted findings与原文支持接口；不重写Answer/Report或把补充背景作为可信证据。三种模式共享同一阅读、评估与引用逻辑，P&E仍是主模式；调度、并发、固定需求和补查ID契约不变。

## 4. 复用与失败处理

先读已有且相关的合法授权来源，再按真实缺口决定是否搜索。复用既有Gateway缓存/singleflight、URL授权与父任务证据传递，不新增跨分支授权广播、不用近似查询合并不同版本需求。

缺失、省略、无匹配或失效证据返回明确诊断与可用定位；不能反复执行完全相同的失败请求来伪装进展。预算/超时用尽保留partial与真实缺口，不伪装completed。评测Gateway额度异常须保留预算原因，不能被通用工具异常误报成供应商网络失败；只调整已确认的该异常分类，不改额度、重试或权限。

## 5. 验证：先恢复质量，再判断是否节省

离线TDD覆盖：不同版本/语言同publisher canonical并存；同实际URL更新仍supersede；实际重定向与URL安全边界；完整条件句跨500字符/多行/相邻片段；去重后原文与引用绑定；预算省略不伪造引用；候选claim不影响评估视图；合法已读anchor无手动记录可收尾；未读、失效、未来引用、前置失败及未完成todo不得收尾；旧checkpoint/Answer/Report兼容；三模式同契约及预算错误分类。全量回归、独立评分环境测试及代码自审通过后才发真实API。

第一步用同一道诊断题、三模式各一次检查恢复，沿用每分支12轮、每运行40 logical/80 Provider/24 Gateway/360秒，研究批次120 logical/240 Provider，评分48 Provider。模型doubao-seed-2.0-lite、temperature=0、输出4096、Answer2000字符、关闭记忆、真实Tavily与HTTP抓取、原Ragas评分器和金答案全部保持。生产默认8及显式.env优先规则不改，不修改用户.env。

诊断恢复门槛：主模式F1不低于旧0.80；不能出现已知取消行为写反或异常聚合遗漏；实际依据题目指定版本。只有F1达标而来源/义务失败仍不能通过。Faithfulness、Goal及全部失败也完整报告，不择优重跑或重评分。0.80不是总体准确率承诺。

第二步才做多题重复联网配对：至少3道新增题加原诊断题，主模式每题每臂2次，旧完整系统臂与候选臂；Workflow/Multi-agent至少在原题各臂一次对照。新题在跑候选前封存题目/金答案/评分器，覆盖版本限制、条件否定、多来源综合；金答案仅供评分，不进入研究模型或工具授权。多题入口仅复用现有eval运行器，解除诊断固定题/模式/重复限制，不新增评测平台。每运行上限不变，批次总上限和源码留样须另做显式预登记；未登记不自动启动多题付费任务。

相同模型/评分口径下逐题及整体报告F1、Faithfulness、Goal、来源约束与完整任务成功率。主模式三项总体均值及成功率不得低于配对旧臂；出现单题明显退步单列分析，不用其他题均分掩盖。样本小不宣称统计意义上的“不下降保证”，逐次结果与有效分母全部保留。

成本同时报告输入/输出及总token、端到端时间、搜索工具请求/实际供应商尝试与重试、fetch/read调用、缺失usage和未知费用。评分用量单列。质量门槛未过则效率优化失败；合格成功样本才作成功成本对照，无匹配成功样本为NA。主模式配对合格成功样本的平均时间、平均总token及平均搜索供应商尝试都不增加，且至少一项下降，才认定达成本轮目标；同时展示所有运行的总开销与成功率，不能只挑便宜成功样本。不承诺固定降幅，不把程序completed、短prompt或少搜索独立当作通过。

## 保留项与实施边界

不新增Agent、服务、依赖、LLM摘要阶段；不改评分器、金答案、模型、生产预算、来源门禁、三模式调度或外部API权限。只替换共享来源身份、阅读/评估视图、研究完成前提和必要预算分类，复用现有评测入口验证；已有不相关dirty更改原样保留。

本规格取代旧效率规格中“必须先登记候选才finish”“候选短摘要优先”的实现选择，其他有效边界不变。已按确认规格完成TDD实施和预登记的三模式各一次研究/评分；保留主模式partial和MA评分超时，不改金答案、评分器或模型。更大付费实验继续受上述恢复门槛限制。
